FEMA Integration Platform utilizes Role-Based Access Control (RBAC) for managing permissions within projects. Each project consists of multiple workflows and users, with each user assigned specific roles that define their actions within the project.

## Project roles

There are four fixed roles. A person's role is set per project, in **Project → Members**; the tenant
owner and tenant administrators can always open a project. Each role includes everything the role
before it can do.

| Permission | Admin | Developer | Operator | Viewer |
|------------|:-----:|:---------:|:--------:|:------:|
| **Workflows** |||||
| View workflows, runs, issues, folders, variables | ✓ | ✓ | ✓ | ✓ |
| Switch a workflow on or off | ✓ | ✓ | ✓ | |
| Edit workflows, folders and variables | ✓ | ✓ | | |
| Publish and delete workflows | ✓ | ✓ | | |
| **Runs and issues** |||||
| Retry and rerun runs, replay and handle issues | ✓ | ✓ | ✓ | |
| **Connections** |||||
| View connections | ✓ | ✓ | ✓ | ✓ |
| Edit connections (for example reauthorise an expired one) | ✓ | ✓ | ✓ | |
| **Releases, MCP services, connector development** |||||
| Request and manage releases, MCP services, connector development | ✓ | ✓ | | |
| **Team** |||||
| View project members | ✓ | ✓ | ✓ | ✓ |
| Add and remove project members, invite, edit the project | ✓ | | | |
| View the audit log of the project | ✓ | | | |

**Operator** is the on-call role: it can keep production running (switch workflows, retry runs,
replay and handle issues, reauthorise connections) but cannot change what a workflow does.

These are fixed roles in the product; there are no custom roles and no Git sync. The permission lists
are pinned by tests, so a change to a role shows up in review.

## Tenant roles

Separately from project roles, a person has a tenant role: **Owner** (the person who created the
tenant), **Admin** (manages users, sign-in rules, workers and everything under *Tenant Settings*),
**Operator** (sees every project but cannot administer the tenant) and **Member** (sees the projects
they belong to). Module permissions (connector development, MCP services) are granted per person in
**Users**.
