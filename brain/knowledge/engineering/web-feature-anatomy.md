# Web Feature Anatomy

What a frontend feature looks like in `packages/web/src/`. The canonical reference is `features/tables/` — when this page and that folder disagree, the folder wins.

## Feature folder

```
features/{feature}/
  api/          # api clients — tables-api.ts, fields-api.ts
  components/   # React components
  hooks/        # react-query hooks — table-hooks.ts
  stores/       # zustand stores, when the feature has client state
  types/
  utils/
  index.ts      # barrel — the feature's public surface
```

Everything crossing the feature boundary goes through `index.ts`. See `features/executions/index.ts`: React components are exported **by name** (`RunsTable`, `StepStatusIcon`), while plain function/constant utils are grouped into one object first (`executionsApi`, `executionUtils`) and re-exported as that object.

## API client and hooks

API client: `features/executions/api/executions-api.ts`. Hooks: `features/executions/hooks/execution-hooks.ts`.

On any query that fetches a page's **primary** data — the table rows, the list, the thing the page exists to show — set `meta: { showErrorDialog: true }`. `QueryCache.onError` in `app/query-client.ts` turns that into the global error dialog. Leave it off for auxiliary queries (feature flags, connector metadata, single-item fetches, filter options, user details) — those should fail silently rather than throw a modal over the page.

## Route

Routes are registered in `app/routes/project-routes.tsx`, composed from `ProjectRouterWrapper` plus guards:

```tsx
...ProjectRouterWrapper({
    path: routesThatRequireProjectId.myFeature,
    element: (
        <RoutePermissionGuard requiredPermissions={Permission.READ_MY_FEATURE}>
            <PageTitle title="My Feature">
                <SuspenseWrapper>
                    <MyFeaturePage />
                </SuspenseWrapper>
            </PageTitle>
        </RoutePermissionGuard>
    ),
}),
```

The page component itself is `React.lazy()`-imported. `requiredPermissions` takes a single `Permission` or an array. Guards live in `app/guards/` — `permission-guard.tsx`, `flag-route-guard.tsx`, `project-route-wrapper.tsx`.

## Flags, gating, translations

- Feature flags: `flagsHooks.useFlag()`, or `<FlagGuard>` / `flag-route-guard.tsx` for whole routes.
- Paid features: `LockedFeatureGuard` on the frontend, `enabled: platform.plan.<flag>` on the query. The backend counterpart is `platformMustHaveFeatureEnabled()`, which returns 402.
- Translations go in `packages/web/public/locales/en/translation.json` **only** — the other locales are generated. Zod validation messages must be keys in that file, not raw English; reuse the `formErrors` constant from `@fema-ipaas/shared` for common ones.

## Editions

Every customer-facing surface must be checked on all five edition paths — CE, EE self-hosted, Cloud freemium, Cloud self-serve paid, Cloud enterprise. Nothing user-visible hardcodes "FEMA Integration Platform": name, colours, and logos come from platform appearance. Community always gets the default theme, Cloud always applies platform branding, EE requires `platform.plan.customAppearanceEnabled`. See `ee/helper/appearance-helper.ts`.

Verify with `npx turbo run lint --filter=web`, or `npm run lint-dev` for the whole repo.

## Gotchas

- **A `packages/web` test runs in the `node` environment by default, so importing anything that touches `window` at module load fails at collection.** `vitest.config.ts` sets `environment: 'node'`; ~26 suites opt into a DOM with a `// @vitest-environment jsdom` docblock on line 1. The failure is a bare `ReferenceError: window is not defined` pointing at a *transitive* import (`embed-provider.tsx` reading `window.opener`, reached via `@/features/projects`), not at the test — so read the stack, don't hunt in your own file. Missing the docblock is why `chunk-reducer.test.ts` was red for as long as it was: CI did not run the web suite at all, so nothing surfaced it.
- **Exported types and constants belong at the *end* of the file**, after the components and logic. Reading a file should start with what it does, not its type declarations.
- **`showErrorDialog` on the wrong query is worse than missing it.** On an auxiliary query it throws a modal over a page that was working fine; on the primary query, omitting it leaves the user staring at an empty table with no explanation.
- **A ref assigned during render (`const ref = useRef(x); ref.current = x`) is stale inside socket/event callbacks.** The value only advances when React commits a render, so two events handled before that commit both read the same base — a read-modify-write (merging a step into `run.steps`) silently drops the earlier event. Read the zustand store directly instead: `useBuilderStore().getState()` (`app/builder/builder-hooks.ts`) always returns current state. Bit the test-workflow widget's progress merge, PR #14453.
- **Builder overlays share one stacking context, so a big `z-` wins over everything — including portalled popovers.** Nothing between an overlay in the canvas panel and `<body>` creates a stacking context (the middle panel is `relative` + `z-auto`; `ResizablePanel` sets only flex/overflow), so a canvas child's `z-index` competes directly with Radix portals. The working ladder: canvas `z-30` (opaque `bg-builder-background` — anything below it is invisible), header and floating corner chrome `z-40`, data selector / canvas controls / popovers `z-50`. That is why the powered-by note at `z-10000` painted over the connector selector.
- **The workflow "download as image" only captures `.react-workflow__viewport`.** `workflowScreenshotUtils` (`workflow-canvas/utils/workflow-screenshot-utils.ts`) clones that one element into an SVG, so anything outside it — the dot-grid background, the powered-by note, canvas controls — is absent unless handled explicitly. Two seams: mark in-viewport chrome you want *omitted* (step chevron, badges) with `data-workflow-screenshot-exclude`; anything *outside* the viewport you want *included* has to be redrawn onto the composited 2D canvas in `composeImageWithCanvasBackground` (that's how the background dots and the powered-by mark get there).
- **The editor is three columns: tools left, canvas centre, config right.** Picking a trigger or action opens `LeftSideBarType.CONNECTOR_PICKER` in the left panel (`builder/left-panel/`, which also hosts the run list and the version list); the right panel is `RightSideBarType.CONNECTOR_SETTINGS` only, split into Action / Input / Output / Error Handling tabs. `builder/connectors-selector/index.tsx` is only the click target that writes `openedConnectorSelectorStepNameOrAddButtonId` + the operation into the builder store. Connectors render as a three-column icon grid (`ConnectorGridItem`), not list rows. The old popover sizing helper (`useAdjustConnectorListHeightToAvailableSpace`, `CONNECTOR_SELECTOR_CLIPPING_THRESHOLD`) is dead for this path — a panel fills its own height. The `Permission.READ_WORKFLOW` guard on the run-history entry lives on the left icon rail; it used to sit on a top-bar button that no longer exists.
- **`Alert`'s `warning` and `destructive` variants ship without a background tint, so a tinted banner has to add one at the call site.** `components/ui/alert.tsx` gives `primary` and `success` a `bg-*-100/10` wash but leaves `warning` and `destructive` transparent (`destructive` sets `bg-card`, which reads as a plain panel on a page background, and unlike `warning` it sets no border colour either). A banner that needs to look like a banner rather than a bordered paragraph passes `bg-warning-100/10` / `bg-destructive-100/10 border-destructive/50` itself — that is what the credits usage alert does. Don't "fix" it in the variant without looking: eight-plus existing warning alerts sit inside dialogs on card backgrounds and were designed against the untinted look. Note also that `--warning-100` and `--destructive-100` are *not* redefined in the `.dark` block of `styles.css` (unlike `--primary-100`), so in dark mode both tints are a very pale hue at 10% over near-black — subtle by accident, not by design.
- **`npx turbo run serve --filter=web -- --mode=cloud` cannot do OAuth2 connections.** The provider redirects to `fema.local` after sign-in instead of your local frontend. Use API-key or basic-auth connections, or run a fully local backend.
- **`--mode=cloud` also floods the terminal with `[vite] http proxy error: /ingest/... ETIMEDOUT 127.0.0.1:3000`.** The mode only redirects the API (`API_BASE_URL` → `https://github.com/lokiworks/fema-ipaas` in `lib/api.ts`); PostHog still posts to the *relative* `api_host: '/ingest'` (a same-origin reverse proxy so ad blockers don't drop ingestion — `providers/telemetry-provider.tsx`, mirrored in prod by the `fastifyHttpProxy` in `server.ts`). Vite proxies `/ingest` to `127.0.0.1:3000`, which isn't running. Cloud flags also turn telemetry *on* (`TELEMETRY_ENABLED` + `EDITION=cloud`), unlike a local CE backend — so posthog-js keeps polling `/ingest/flags` and flushing `/ingest/e` every few seconds. Harmless, but note the same setup sends real dev clicks to production PostHog whenever `/ingest` does resolve; the clean fix is skipping `posthog.init` under `import.meta.env.DEV`.
- **`packages/web`'s lint script only globs `src/**`, so nothing under `packages/web/test/` is ever linted** — not by CI's `lint` job, not by `npm run lint-dev`. Running `npx eslint 'test/**/*.{ts,tsx}'` from `packages/web` today reports 21 errors nobody has seen, so a new web test needs a manual eslint pass or it ships with errors. Most common trap: `testing-library/render-result-naming-convention` fires on any local helper whose name merely *starts with* `render` even when testing-library is not involved — renaming `render` to `renderTabText` does not silence it, only a name that doesn't begin with `render` does.
- **`RoutePermissionGuard` used to redirect to /404 while permissions were still loading, so every hard refresh of a workspace route 404'd.** `useAuthorization().checkAccess` is `!isLoading && granted.has(p)` — indistinguishable from "denied" during the `/v1/workspace-members/me` request. Clicking a tab worked (react-query had the role cached, `staleTime` 5min); pasting a URL or pressing F5 did not. The guard now renders `<RouteLoadingBar />` while `isFetchingWorkspaceRole`. Any new guard reading `checkAccess` needs the same three-state handling — loading is not denied.
- **A type error in a `packages/web` *test* file blocks the whole app behind a full-screen Vite overlay.** `vite-plugin-checker` runs in `buildMode` against `packages/web/tsconfig.json`, which pulls in `tsconfig.spec.json`, so a stale fixture in `*.test.ts` paints `vite-error-overlay` over the running app — the sign-in form sits underneath it, unclickable. `tsc --noEmit -p tsconfig.app.json` will *not* reproduce it (app config excludes tests); use `npx tsc -b tsconfig.json` from `packages/web`.
- **`packages/web/public/locales/zh/translation.json` was largely Traditional Chinese with Activepieces-era vocabulary** — `Workflow` rendered as 流, `Connector` as 块 (a literal carry-over of "Pieces"), `Publish` as 重新上架, plus ~600 entries in Traditional characters. Converted with `opencc` `tw2sp` and a term table. When adding zh strings, check the terminology against the nav: 工作流 / 连接器 / 连接 / 触发器 / 动作 / 步骤 / 发布, and keep it Simplified.
- **Module-level `t()` calls resolve before i18next finishes loading, so they render the English key.** A `const NAV_ITEMS = [{ label: t('Home') }]` at module scope evaluates at import time. Wrap it in a function called during render (`buildNavItems()`) — that is why `auth-landing/auth-backdrop.tsx` builds its nav, recent list and conversation from functions rather than constants.
- **The connector selector's Approvals tab was hardcoded to five connectors this fork does not ship** (`discord`, `microsoft-teams`, `microsoft-outlook`, `gmail`, `telegram-bot`), so every open of the picker fired five 404s at `/v1/connectors/{name}` and the tab rendered empty. Removed along with `approvals-tab-content.tsx`. Nothing in `packages/connectors` exposes a `request_approval*` action today — if approvals come back, derive the list from the installed connectors rather than hardcoding package names.
- **Roughly 45% of `en/translation.json` was dead, and a `t('...')` scan will not find it.** 1156 of 2540 keys had no occurrence anywhere under `packages/` or `tools/` — the residue of this fork removing billing/plans, agents + MCP, git sync and environments, audit logs and event streaming, and the old project-settings surfaces. Auditing them needs a **string-literal** scan, not a call-site scan, because 27 sites call `t(variable)`: `t(role)`, `t(label)`, `t(fnDef.description)` and friends. Every one of those variables resolves from a source-level constant table or enum (`DefaultWorkspaceRole`, `ROLE_DESCRIPTIONS`, `DATE_RANGE_PRESET_LABELS`, `packages/core/formula/src/lib/function-registry.ts`), so the safe rule is: a key is live iff its exact text appears as a string literal somewhere under `packages/`. Keep the corpus to `packages/` + `tools/` — widen it to the repo root and `docs/`/`brain/` prose, which still documents the removed features, 'rescues' ~100 genuinely dead keys. One blind spot the scan cannot see through: a key whose only literal is its own dead definition still reads as live — 7 of the 8 entries in `packages/core/shared/src/lib/form-errors.ts` have zero `formErrors.<x>` call sites but survive.

- **Opening a step's 入参 tab used to silently fork a draft, so a just-published workflow immediately read "有未发布的更改".** The step form autosaves from its resolver whenever the cleaned values differ from the snapshot, and merely *rendering* the input tab produced a difference twice over: `getDefaultValueForProperties` materialised display-only `PropertyType.MARKDOWN` props into the step input as `''`, and `updatePropertySettingsSchema` unconditionally wrote `schema: {}` for a dynamic property whose resolved schema was empty. Net effect: viewing parameters un-published the workflow in the user's eyes and lit up "放弃更改". Both now no-op when there is nothing real to write — markdown props are skipped unless a stored value already exists (so legacy rows don't churn in reverse), and an empty schema is not persisted over an absent one. **When touching that form, verify with a published workflow: click every tab and confirm the header stays clean.**
- **`formatUtils.convertEnumToHumanReadable` is not i18n** — it title-cases the enum, so `SUCCEEDED` renders as "Succeeded" inside an otherwise Simplified-Chinese table. Execution status now goes through `executionUtils.getStatusLabel`, an exhaustive `switch` over `ExecutionStatus` returning `t(...)`; the same English-in-a-Chinese-page leak still exists for connection status, project type and connector names at the other `convertEnumToHumanReadable` call sites.
- **A zh translation must not bake in trailing punctuation the caller supplies.** `"Today": "今日："` rendered as `今日：, 下午5:44` because `format-utils.ts` appends its own `, `. Four entries had this shape; `Took` was also a mistranslation (`取得：` for what is a duration label, now `耗时`). Check how a key is composed at the call site before translating it.
- **`packages/web` unit tests now initialise real i18next** via `test/setup-i18n.ts` (`setupFiles` in `vitest.config.ts`), loading `public/locales/en/translation.json` with the ICU plugin. Before this, `t()` returned the bare key, so any test asserting user-visible copy had to `vi.mock('i18next')` and assert nothing meaningful — `src/lib/test/utils.test.ts` did exactly that and its expectations went stale silently. Prefer the real bundle; a failing assertion there means the copy actually changed.
- **A brand-new workflow used to land on an empty canvas with no panel open.** `determineInitiallySelectedStep` had an explicit `if (isNewWorkflow) return null` — a leftover from when selecting the empty trigger popped a canvas *popover*, which would have been obnoxious on load. With the picker living in the left panel that reason is gone, and the early return just left the user staring at a "选择触发器" node with no visible next action. Removed; the empty trigger is now selected on mount and `createCanvasState` / `createConnectorSelectorState` seed `CONNECTOR_PICKER` + `UPDATE_TRIGGER` so the panel actually has content.
- **The connector results list carried `min-w-[350px]` inside a 260px panel**, so every row overflowed ~90px and its description was hard-clipped by the ancestor's `overflow-hidden` instead of ellipsizing — `truncate` looked correct in the DOM (`scrollWidth === clientWidth`) because the element had simply been given its intrinsic width. A leftover from the 480px right-hand selector. When a `truncate` refuses to ellipsize, measure the element's `right` against its panel's `right`, not just scroll vs client.


- **`/projects/:id/settings` froze the browser tab in an infinite redirect.** `SettingsRerouter` sent every hit to `/settings/team`, a route **nothing defines** — the old project-settings page is now the gear-icon `ProjectSettingsDialog`, not a route. The 404/guard path bounced it straight back, and because each navigation opens a socket.io connection the tab died with `WebSocket ... failed: Insufficient resources`. Measured 2263 navigations in 5 seconds. Worse, `determineDefaultRoute`'s last fallback *returned* `/settings`, so a user with neither `READ_RUN` nor `READ_WORKFLOW` hit the freeze immediately on sign-in. `/settings` now redirects to the project home and the fallback points there too. **When deleting a page, grep for `Navigate to=` and the route table — a redirect to a removed route is a hang, not a 404.**
- **A connector's markdown block lives in `description`, and its i18n key is the *raw* source string including `{{placeholders}}`.** `Property.MarkDown({ value })` stores the text in `description` (covered by `triggers.*.props.*.description`), so translation does work — but interpolation of `{{webhookUrl}}` / `{{webhookTimeoutSeconds}}` happens in the **web** at render time (`step-settings/connector-settings/index.tsx`), long after the server translated. The webhook connector's `syncMarkdown` entry had been generated from an already-interpolated, slightly different string (`30` instead of the placeholder, plus a trailing space after `URL.`), so that one block silently stayed English while the two neighbouring blocks rendered Chinese. A stale key fails silently — there is no missing-translation warning. **After editing markdown copy in a connector, update the matching key in `src/i18n/*.json` byte-for-byte and rebuild (`npm run build` in the connector copies `src/i18n` into `dist`).**
- **Percentage-height children collapse to nothing under `items-end`.** The home page's "Runs over time" card rendered as an empty box: its columns were `flex-1 flex-col justify-end` inside a `flex h-32 items-end` row, so each column shrank to content height (0) and the bars' `height: N%` resolved against 0. `items-stretch` fixes it. The same card also only received days that had runs — the SQL aggregate correctly omits empty days, so the *frontend* fills the window (`buildContiguousTrend`) and paints a `bg-muted/40` track per day, otherwise a 7-day range renders as one fat bar.
- **Fixed-width tabs silently truncate in the 260px left panel.** `ConnectorSelectorTabs` gave each trigger `w-[85px] shrink-0` with `gap-3`; four tabs need 308px, and the list's scrollbar is hidden by CSS (`[&::-webkit-scrollbar]:hidden`), so the last tab was simply cut off with no scroll affordance. Now `flex-1 min-w-[56px] max-w-[85px]` with `gap-1`. **Any fixed `w-[...]` inside that panel needs re-checking against 260px.**
- **`packages/web/test/setup-i18n.ts` only helps files that don't mock i18next.** It initialises the real en bundle for every suite, but `vi.mock('i18next', ...)` in a test file still wins and makes `t()` return the key. If assertions on user-visible copy look like key names, that mock is why.


- **A `Navigate to=` pointing at a route nobody defines is a browser hang, not a 404.** Two shipped instances: `/settings` → `/settings/team` (page became the gear-icon dialog) and `/tenant/security` → `/tenant/security/sso` (the folder is named `sso` but the route registered is `/tenant/security/authentication`). Each bounced against a guard forever, opening a socket.io connection per hop until the tab died with `Insufficient resources`. A cheap static guard catches the whole class: collect every `<Navigate to="...">` target across `packages/web/src` and diff it against the `path:` entries in `app/routes/*` plus `routesThatRequireProjectId`.
- **The audit-log page rendered raw English because the summary lives in `@fema-ipaas/shared`.** `summarizeApplicationEvent` builds template literals in a framework-agnostic package with no i18n, and the table also printed the bare enum (`workflow.run.finished`) as the Action column. Translation now happens in the web via `auditEventUtils.summarize` / `.actionLabel` (`features/audit-events/utils/`), which switches over all 25 `ApplicationEventName` values and all 27 `WorkflowOperationType` sub-cases with ICU params; the shared function survives only as the `default:` fallback. **Adding a new `WorkflowOperationType` means adding a case in both places, or the audit row silently reverts to English.**
- **`t('...')` with a key that isn't in `translation.json` renders the English key, silently.** The whole tenant admin area looked "not translated" but was already wrapped in `t()` — 23 keys were simply absent from both locale files, so i18next fell back to the key. Grepping for `t('` literals under a route folder and diffing against `en/translation.json` finds these in one pass; the UI gives no warning.
- **A wrong translation is invisible to any automated English-leakage check.** The tenant sidebar read 「工人」 for Workers (labourer, not worker node), 「保健」 for Health (healthcare), and 「A. 概况」/「B. 基础设施」/「A. 工 人」 carried stray ordering prefixes and a stray space from a machine pass. All are valid Chinese, so a scan for Latin characters passes them. Re-read admin nav labels by eye after any bulk translation import.


- **A collapsed sidebar turns every nav item into an unnamed button.** `sidebar-nav-item.tsx` and `sidebar/project/index.tsx` render the label as `{!isCollapsed && <span>{item.label}</span>}`, so in icon-rail mode the button has no text, no `aria-label` and no accessible name at all — a screen reader announces "button, button, button". The label is already in hand; set `aria-label={item.label}` unconditionally rather than relying on the visible span. Same class: `SidebarUser`'s avatar trigger and `sidebar-toggle.tsx` (whose tooltip text is the obvious label to reuse).
- **`Dialog`/`Sheet` shipped a hardcoded English "Close"** — both the `sr-only` label and, in `DialogFooter`'s `showCloseButton`, a *visible* button. Every dialog in the app inherited it. The `Close` key already existed in both locales.
- **Radix warns at runtime when a `DialogContent` has no `DialogTitle`** (`requires a DialogTitle ... to be accessible for screen reader users`). The project-settings dialog builds its own sidebar chrome and never used `DialogHeader`, so it tripped this on every open. A `<DialogTitle className="sr-only">` satisfies it without changing the visual design.
- **Auditing for accessible names is cheap and catches a whole class the eye misses.** The sweep counts a button as named if it has text, `aria-label`, `title`, or an inner `img[alt]` — that last one matters or the logo button reads as a false positive. Current known-nameless clusters left: the shared `Switch` primitive (enable/disable toggles) and a handful of icon-only actions on tenant setup pages.
- **A dialog with a hardcoded height is mostly empty whenever the content is short.** `new-connection-dialog.tsx` was `h-[680px] max-h-[680px]`; with only the two connectors that require auth, ~400px was blank above a lone "Close" button. `max-h-` alone lets the flex column size to content and still scroll when the list is long.


- **`public/assets/full-logo.svg` clipped its own wordmark.** The `viewBox` was `0 0 176 32` while the `<text>` starts at x=44 and measures ~144px, so the last glyph fell outside the box — the sign-in card showed "Integration Platfor". Nothing in the DOM looks wrong (the `<img>` renders at the viewBox aspect and its container has room), so measure inside the SVG: `document.querySelector('text').getBBox().x + width` against `svg.viewBox.baseVal.width`. Now `0 0 200 32` with the text ending at 188.
- **An accessible-name audit must count `<label for>` and `aria-labelledby`, or it fabricates work.** Radix's `Switch` renders a `<button>`, and `<button>` *is* a labelable element, so a sibling `<FormLabel htmlFor>` already names it — a naive probe reports it as nameless and tempts you into adding a redundant `aria-label`. The appearance-section switch is exactly this case.
- **Icon-only row actions are the largest nameless-button cluster**, and they repeat per table: row checkbox, favourite star, and the `MoreHorizontal` dropdown trigger each need their own label. Where a `Tooltip` already wraps the control its `TooltipContent` text is the label to reuse (`aria-label={isPinned ? t('Remove from favorites') : t('Add to favorites')}`). `SelectUtilButton` takes this further — it already has a `tooltipText` prop, so labelling it once fixes every file-picker and util button in the connector property forms.
- **The audit's anonymous routes need their own browser context** (`ANON:` prefix), and the generic end-of-loop `page.screenshot` will silently overwrite the anon screenshot with the logged-in page if you forget to skip it. `/sign-up` redirects to `/sign-in` once a user exists, so a clean result there is expected, not a bug.


- **`pathsToValuesToTranslate` never covered array sub-properties, so every connector's `Property.Array` fields stayed English.** The Web Form trigger rendered 「字段名称」's neighbours as raw `Field Name` / `Field Type` / `Field Description` / `Required` in an otherwise Chinese form. The path list (`packages/connectors/sdk/src/lib/i18n.ts`) had `triggers.*.props.*.displayName` but nothing for `props.*.properties.*`; added both the action and trigger variants plus their nested dropdown `options.options.*.label`. This is a *systemic* fix — it unlocks nested labels for every connector, but each connector still needs the matching keys in its own `src/i18n/*.json`.
- **The API loads `@fema-ipaas/connector-sdk` from `dist`, not source.** Its `package.json` `main` is `./dist/src/index.js`, so an edit to the SDK does nothing until `npm run build` in that package *and* a dev-stack restart — connector metadata is also cached in the running API. Same for a connector's own `src/i18n/*.json`: its build script copies them into `dist/src/i18n/`. Editing the source and re-reading the page will show you the old strings and send you hunting for a bug that isn't there.
- **Reusable icon-button wrappers already carry the label you need.** `SelectUtilButton` (`tooltipText`) and `CanvasControlButton` (`tooltip`) each wrap a `Button` in a `Tooltip`; adding `aria-label={tooltip}` inside the wrapper names every instance at once — that one line covers the whole canvas control bar (zoom, fit, screenshot, pan, minimap, note). Prefer fixing the wrapper over labelling call sites.
- **Adding `aria-label` to nav items broke Playwright selectors that matched on visible text.** `getByRole('button', { name: '连接器' })` had been unambiguous; once the sidebar item was labelled it matched two elements and every builder script failed with a strict-mode violation. Scope to the rail with `button[aria-label="连接器"][data-slot="tooltip-trigger"]`. Expect this whenever an a11y pass lands.
- **More "valid Chinese but wrong" translations found by reading screenshots, not by any scan:** `Started` → 「正在运行」 (it labels a run's *start time*, so the banner read 「运行成功 - 正在运行: …」), `Items`/`Loop on Items` → 「项目」/「循环项目」 (project, not list item), `Add Item` → 「添加项目」, `Read` (the action-classification badge) → 「已读」 (message-read, not read-operation). Five keys also have empty-string values (`Subject`, `Credits`, `Seats`, `Workflow run`, `Price`) — all dead residue from the removed billing surfaces, no call sites.


- **The public form page shipped a hardcoded "Built with fema" mark** — English copy, the internal package name in lowercase, and an upstream logo path baked into `show-powered-by.tsx`. The form page is the most externally-visible surface in the product, so this is the sharpest white-label violation in the app. It now reads `t('Built with')` plus `branding.websiteName` / `branding.logos.logoIconUrl` from `flagsHooks.useWebsiteBranding()`. The `SHOW_POWERED_BY_IN_FORM` flag only controls *whether* it renders, never *what* it says.
- **`<FormControl>` wrapping a Fragment silently drops every prop it was meant to forward.** `FormControl` is a Radix `Slot`, so `<FormControl><>…</></FormControl>` in `features/forms/components/workflow-form.tsx` handed `data-slot`, `id` and `aria-describedby` to a `React.Fragment` — React logs "Invalid prop supplied to React.Fragment" and *none of them reach the input*. Give the Slot a real element (a `div`). Label association happened to survive here only because the inputs set their own `id` and the label its own `htmlFor`.

## Gotchas
- **A flex child with `grow` but no `min-w-0` refuses to shrink and pushes its siblings off screen.** `PageHeader`'s left block did exactly that, so at 768px the builder's 调试 / 放弃更改 / 发布 buttons sat past the viewport — you could not publish a workflow. `min-w-0` on the growing block plus `shrink-0` on `rightContent` fixes it for every page that uses the header.
- **`min-w-0` has to be on every element in the chain.** After fixing `PageHeader`, the builder title still overlapped the buttons because `BreadcrumbItem` and `BreadcrumbPage` sat between the constrained parent and the truncating div. And a fixed `max-w-[500px]` on the title is not a constraint at 768px — it is wider than the space available. Watch for the sibling symptom too: over-shrinking made 「个人项目」 wrap one character per line until it got `whitespace-nowrap`.
- **Extreme data is what makes truncation bugs visible.** Seeding a workflow whose name is ~70 characters and a variable named `VERY_LONG_...` immediately overflowed the audit log's 详情 column by 354px; every normal-length row had hidden it. The column now uses `TextWithTooltip` inside a `min-w-0 max-w-[min(52vw,640px)]` wrapper, per the repo rule that overflowing text uses that component.
- **A table cell grows to its content, so `truncate` alone does nothing there.** The wrapper needs an explicit max-width; `truncate` on the `<p>` only takes effect once something upstream bounds the width.

- **Props placed before `{...spread}` are silently overridden.** The canvas step node ends with `{...attributes} {...listeners}` from dnd-kit's `useDraggable`, whose `attributes` already carry `role`, `tabIndex` and `aria-pressed`. The `role`/`tabIndex` I thought I had added were dnd-kit's all along — the nodes were already focusable — and my `aria-pressed` was wiped. `aria-pressed` on a draggable means "grabbed", so selection state has no business there; the keyboard fix is just an `onKeyDown` that selects, which survives because no `KeyboardSensor` is configured and `listeners` therefore has no `onKeyDown`.
- **Prove a canvas interaction with a state change, not with text on the page.** Asserting "the panel mentions 代码" passed before the fix did anything, because that word was already on screen. The honest check is: click node 0, then keyboard-focus node 1 and press Enter, then read `border-primary` across all nodes and assert it moved from `[true,false]` to `[false,true]`.
- **A regex over `<DataTable[\s\S]{0,3000}?/>` reports false gaps twice over** — it matches `DataTableColumnHeader` and friends unless the name is bounded with `(?![A-Za-z])`, and a 3000-character window truncates before reaching a prop near the end of a long call. Twelve real call sites read as 69, then as "none wired". Grep the file for the prop to confirm before believing either number.

- **A failed list rendered as "you have nothing yet", which is a lie.** After the error dialog was dismissed, runs and connections showed their empty state and automations showed the first-run onboarding — telling someone with plenty of workflows to create their first one. `DataTable` now takes `isError` and renders 「这个列表加载失败 / 刷新页面重试」 instead of the empty state; the automations page also excludes `isError` from `isEmptyState`.
- **A stuck loading state kept hammering a failing server.** `use-automations-data`'s `isLoading` never went false on error, so 50 skeletons animated forever and the component kept remounting: `/v1/folders` was requested 18 times where healthy queries stopped at 4 (1 + 3 retries). Deriving `isError` from the three queries and gating `isLoading` behind `!isError` cleared the skeletons within 20s and dropped the request count to 8.
- **A health check that cannot run is not "checking".** `toStatus(undefined)` returned `'loading'`, so disk/RAM/CPU sat on 「检查中」 forever once the query failed. It now takes the query's `isError` and reports a distinct `unavailable` status.
- **The automated dark-mode contrast check is worthless here and this is the second time it fooled me.** The palette is `oklch()`, which neither a regex nor `canvas.fillStyle` normalizes, so every element reports luminance 0 and the sweep "finds" a low-contrast problem on every page. Dark mode has to be eyeballed from screenshots.

- **The error dialog needs ~10 seconds to appear, because `QueryCache.onError` fires only after React Query exhausts its retries.** Asserting at 5s showed 8 of 10 pages failing silently; at 16s only two genuinely did. When testing failure states, wait past the retry budget before concluding anything.
- **Inject failures without breaking the app shell, or you measure the wrong thing.** Failing every `/v1/**` call blanks every page, because the shell itself needs `/v1/flags`, `/v1/tenants/:id`, `/v1/projects`, `/v1/users/:id` and `/v1/project-members/me`. Allow those and fail only the page's own endpoints; trace a normal load first to learn which is which.
- **`projectCollection` runs on its own bare `new QueryClient()`, so the global error dialog never covered it.** The project list backs the switcher and the tenant projects page, and a failure there was silent everywhere. That client now shares the same handler. Watch for this whenever a feature builds its own QueryClient — the `QueryCache.onError` in `app/query-client.ts` only sees the main one.
- **`features/` may not import from `app/`** (`import/no-restricted-paths` enforces the one-way layering). Sharing the dialog helper meant moving it down into `components/custom/error-dialog/`, which both layers may import; putting it in `app/query-client.ts` and importing upward fails lint.
- **`meta` is typed as `QueryCollectionMeta`, so `showErrorDialog` alone will not compile** — every call site writes `meta: { showErrorDialog: true, loadSubsetOptions: {} }`.

- **Clickable rows were unreachable by keyboard on both primary navigation paths.** The scan is `<div|span|li|td|tr|p …>` carrying `onClick` with no `role`, `tabIndex` or `onKeyDown` — 42 hits. The two that mattered were `DataTable`'s two `<TableRow>` blocks (runs, tenant projects) and the three row wrappers in `automations-table.tsx`, i.e. opening a run or a workflow. Rows now carry `tabIndex={0}` plus a focus ring, and Enter/Space activates.
- **Reuse the existing click path instead of widening the handler type.** `onRowClick` types its third argument as `React.MouseEvent`, so a keyboard event cannot be passed. `e.currentTarget.click()` on Enter dispatches a real click that flows through the same cell-index logic, which avoids touching the prop type and every consumer.
- **Guard a row-level `onKeyDown` with `event.target !== event.currentTarget`.** Without it, pressing Enter on a star or menu button inside the row also fires the row handler and navigates away. Verified explicitly: focus an in-row button, press Enter, assert the URL did not change.
- **Two-thirds of that scan's hits are noise; classify before fixing.** Eleven were `onClick={(e) => e.stopPropagation()}` wrappers, two were cell wrappers that only intercept the checkbox column (the checkbox itself is focusable), and most of the rest are XYFlow canvas nodes and edges, which have their own interaction model and need a separate look.

- **Two components were both writing `document.title`.** `PageTitle` sets `<page> | <websiteName>` per route while `ThemeProvider` set `document.title = branding.websiteName` inside its theme effect; whichever ran last won, so project pages showed a page name and tenant and auth pages showed only the brand. The theme provider no longer touches the title — `PageTitle` already appends the tenant's brand, so white-labeling is unaffected.
- **Route `title=` props are translation keys, not output.** All 19 remaining attribute hits are `<PageTitle title="Workflows">`; translating inside `PageTitle` fixed every browser tab in one edit instead of at 19 call sites. Before "fixing" a hardcoded-looking attribute, check whether the consumer already runs it through `t()`.
- **A third i18n blind spot: string defaults on props.** `NotFoundPage` renders `t(buttonText)` with `buttonText = 'Go Home'` as a default parameter, so the literal never appears inside a `t('…')` call and both earlier scans missed it — the 404 button stayed English. The scan that finds this shape looks for `t(<identifier>)` and then that identifier's string-literal default in the same file.

- **Scanning `t()` keys misses text that never reaches `t()` at all.** The earlier sweep compared every `t('…')` literal against the bundle and reported zero gaps, yet 14 user-visible strings sat as bare JSX text nodes — `Sync from Cloud` on a toolbar button, `No data available`, `Need Help?`, `Please wait...`, the shadcn `Toggle Sidebar` / `Next slide` sr-only labels, and five English strings inside the decorative builder mock on the sign-in page. The regex that finds them is `>\s*([A-Z][A-Za-z][A-Za-z ,.'!?&/-]{6,})\s*<` over `packages/web/src/**/*.tsx`.
- **Inserting an import after the first `import` line breaks a multi-line import.** `carousel.tsx` opens with `import useEmblaCarousel, {` spanning three lines, so a naive "insert after the first import statement" landed inside the braces and the file stopped parsing. Lint caught it as `Parse errors in imported module`; anchor on the end of the import block, not the first line.

- **Diff the server's routes against what the web app actually calls — it finds whole features with no UI.** Enumerating `app.<method>('…')` per registered prefix and checking each literal path against `packages/web/src` left 21 routes; most are engine/worker RPC or Prometheus scraping, but `GET /v1/health/diagnostics` was a fully working operator surface (database/redis/storage latency, deployment config, per-instance CPU/RAM/disk/event-loop delay) with nothing rendering it. It is now the 诊断 tab on the health page. The same sweep is what surfaced the missing invite UI.
- **Check whether a translation key is already spoken for before reusing it.** `Dependencies` was already 「依赖关系」 for npm packages in the code editor; reusing it for infrastructure services read as package dependencies. The new card uses `Infrastructure dependencies`.
- **A server that sends English prose in a data field leaks it straight into a translated UI.** `measureStorage` returned ``detail: `FILE_STORAGE_LOCATION=DB — no S3 round-trip to measure` ``. It now returns `detail: null` and the client renders a translatable sentence when a reachable check has no latency to report — the deployment card already shows the storage location, so nothing was lost.

- **Compare zh values against en to find what was never translated.** Thirteen entries were byte-identical to English, mostly ICU plural keys (`invitationsSentCount`, `rowCount`, `runsRetriedNote`), so a toast rendered `1 invitation sent` in a Chinese UI. Filter out the legitimate matches first — proper nouns like `Webhook`, `JSON`, `UTC` and placeholders like `HTTP {status}` are meant to be identical.
- **Hunt orphan locale keys against the whole monorepo, not just `packages/web/src`.** Keys reach `t()` from connector metadata, shared enums (`t(role)` where role is `DefaultProjectRole`) and server error strings, so a web-only scan called 48 keys dead when only 23 were. Also unescape the key before comparing: a key containing a real newline never matches source that writes `\n`. The 23 that survived both checks were safe to delete, verified by re-running the audit sweep afterwards.

- **Scan every `t('…')` key against `en/translation.json` — 23 were missing.** i18next falls back to the key itself, so a key that was never added renders as raw English in a Chinese UI and no runtime error appears. The regex over `packages/web/src` for `t('…')` / `t("…")` literals, minus anything containing `${`, finds them in one pass; it also caught `t('Help translate FEMA Integration Tenant →')`, a hardcoded product name that the white-label rule forbids.
- **Project settings tabs were `<div onClick>`, so the members panel was unreachable by keyboard.** They are now `role="tab"` buttons inside a `role="tablist"` with `aria-selected`. A quick signal for this class: `getByRole('tab')` returning `[]` on something that visibly is a tab strip.

- **`<DialogTrigger asChild>` around a fragment is a recurring shape in this repo, and the console names the prop.** `edit-global-connection-dialog.tsx` wrapped `<>` holding a `TooltipTrigger` plus `TooltipContent`, so Radix's Slot forwarded `type="button"` into a Fragment. The warning text ends in the offending prop name (`… can only have key and children props. | type`), which is enough to find it. Both this and `rename-connection-dialog` were controlled dialogs whose button already called `setIsOpen(true)`, so deleting the trigger layer entirely is the fix, not adding another wrapper.
- **A `DialogContent` with no `DialogDescription` warns on every open.** Radix wants `aria-describedby`; the connector picker and the connection form each needed one line. Watch for the warning firing *before* you open anything — that means the offending component is on the page, not in the dialog you were testing.
- **`useDeepCompareEffect(fn, [page?.data])` warns while the query is loading**, because the dep array is `[undefined]` — all primitives — and `react-use` refuses that. `[page?.data ?? []]` keeps the deep comparison and removes the warning; the effect body already defaulted to `[]`.
- **Fourteen zh strings used 项目 to mean "item".** Since 项目 is now the Project entity, 「删除选择的项目」 on a workflow table reads as deleting projects. They are now 条目. - **A form field with only a placeholder has no label.** The create-folder dialog's name input relied on `placeholder={t('Folder Name')}`, which disappears the moment someone types. Its `FormItem` now carries a real `<Label htmlFor>`.
