## 要点

**新旧接口。** 北森有三套对外接口：新版 V3（`open.italent.cn` 是文档站点，覆盖组织员工、薪酬、假勤、绩效、继任与发展、Account、新招聘）、老版 V2（只维护存量，不再迭代）、招聘 2.0（集团版招聘，同样只维护存量）。文档明确写「新对接客户都通过新版接口对接」，对接流程只适用于 V3。

**调用流程。**

1. 北森实施顾问或租户管理员在 italent 的「企业设置 → 授权管理」里，给某个账号授予「开放应用连接」租户管理员身份。
2. 用该账号登录开放平台的管理者后台，创建连接器，拿到 Key 和 Secret。
3. 在连接器详情里逐个添加要调用的接口权限。
4. 可选：在「OpenAPI 调用授信 IP」里加调用方的 IP 段。
5. `POST {域名}/token`，请求体 `grant_type=client_credentials`、`app_key`、`app_secret`，换 `access_token`，有效期 2 小时，期间重复获取返回同一个令牌。
6. 带令牌调用各模块接口。

**三套环境。** 正式租户和测试租户共用同一个生产接口域名，只是租户不同，测试租户由北森实施顾问开通。沙箱环境是单独的域名（`openapi.italent-dev.cn`，令牌在 `/token`），只有买了 PaaS 平台的客户才有。

**限频。** 每租户每接口 50 次/秒、3000 次/分钟，具体以各接口文档为准。同一租户下多个连接器加了同一个接口，一秒内累计不能超过 100 次。触发后返回 `429 API rate limit exceeded`，当天不可恢复，次日零点恢复，**上限不能调整**。

**时间窗接口。** 官方推荐的员工同步入口是「根据时间窗滚动查询变动的员工与单条任职信息」（`/TenantBaseExternal/api/v5/Employee/GetByTimeWindow`），组织、职位、职务各有同类接口；要历史任职改用「员工与多条任职」接口。

- `timeWindowQueryType` 不传默认 1，按修改时间匹配，**每天凌晨北森重算司龄等系统任务也会刷新它**，所以会返回大量无业务变化的员工；传 2 按业务修改时间匹配，只含入职、转正、调动、编辑等人工业务操作。
- 时间范围最早 1900-01-01、最晚 9999-12-31。
- 每页最多 300 条，翻页间隔**不能超过 10 秒**，超过则下一页取不到。官方建议每页取到后先放进内存，取完所有页再处理。
- 只返回审批通过或生效的数据，不返回审批中的；只能返回最新主职或当前生效主职，不返回兼职和历史失效的任职。
- 常见漏数据原因：`employType`、`empStatus`、`isGetLatestRecord`、时间参数、`timeWindowQueryType`、`isWithDeleted`、`withDisabled`、没翻完页、传了 `extQueries`、测试租户与正式租户混用。

**离职和待入职。**

- 离职生效或审批通过的任职记录，用时间窗接口取；离职审批中的，要用另一个「获取任职审批中的数据」接口。离职交接人落在离职任职记录上。
- 员工状态 `employeeStatus`：1 待入职，2 试用，3 正式，8 离职。
- 离职审批已通过、最后工作日在未来的员工，会在传了「审批通过和生效」且「取最新任职」时被返回成 8-已离职。只想要已生效的离职，要把 `approvalStatuses` 只传 4，`isGetLatestRecord` 传 false。
- 想在入职日期之前就拿到「已操作入职、入职日期在未来」的员工（门卡、账号提前开通），条件是 `approvalStatuses` 含 4-生效、`isGetLatestRecord` 为 true、`serviceType` 为 0-主职，`empStatus` 至少含 2 和 3。
- 离职再入职看当前主职任职记录的 `changeTypeOID`，等于 2 就是重聘。

**升级公告。** 2026-02-26 的公告：全部组织员工数据获取类接口的请求参数 `enableTranslate`（动态翻译）停止支持，响应里的 `translateProperties` 默认返回 null。2026-03-13 前已完成对接的存量客户暂不受影响，从该日起新对接的客户必须改用官方数据源接口取翻译文本。

**支持渠道。** 先用 Postman 之类的工具用同样入参自查；仍然不通，发邮件到 `supportapi@beisen.com`（承诺 24 小时内回复，要附业务场景、接口、请求内容、报错和出入参），或通过实施顾问提交付费工单（需提供对接方案）。

## 对本仓库的影响

- **取令牌字段已被官方文档证实。** 连接器用的 `app_key`、`app_secret`、`grant_type=client_credentials` 与「接口调用流程」一致，此前靠故意发错误请求探出来的结论（见 `brain/knowledge/connectors-engine/building-connectors.md`）现在有一手来源。
- **时间窗接口走的不是文档推荐的路径，需要核对。** 触发器 `employee-changed` 和动作 `search-changed-employees` 调的是 `/TenantBasePublicApiV2/v2/employee/timewindow/search`，而官方文档推荐的是 `/TenantBaseExternal/api/v5/Employee/GetByTimeWindow`；连接器里组织、任职等其他动作用的已是 `/TenantBaseExternal/api/v5/`。入参也不同：连接器只传 `startTime`、`stopTime`、`capacity`、`isWithDeleted`、`scrollId`、`columns`，没有 `timeWindowQueryType`、`approvalStatuses`、`isGetLatestRecord`、`empStatus`、`employType`。路径前缀带 V2，是否就是文档说的「已不再迭代的老版 V2」，没有文档直接证实，要拿到真实租户或到开放平台文档站点核对；如果是，主线的取数入口应换成 V3 接口。
- **不传 `timeWindowQueryType` 会按修改时间匹配。** 若切到 V3，默认值 1 会让每天凌晨的司龄重算也触发员工变动，主线的触发器会被无业务变化的员工刷屏，需要显式传 2。
- **离职处理的口径要对齐官方文档。** 主线里「员工离职 → 停飞书账号」应取生效的离职任职记录（`approvalStatuses` 只含 4）；若误传审批通过，最后工作日在未来的员工会被提前停号。反过来要提前开通账号的新员工，取数条件见上面的待入职一条。
- **翻页间隔 10 秒。** 触发器 `drainTimeWindow` 是先把所有页取完再返回，每页之间没有业务处理，符合官方建议；但如果以后在翻页循环里加了逐条处理，会超时。
- **429 已按「当天不可恢复」处理（连接器 0.2.1）。** `beisenCommon.callApi` 把 HTTP 429 和 200 响应体里的 `API rate limit exceeded` 都转成 `HTTP 429: ... 次日 00:00 才能再调` 的错误，问题中心按 HTTP 状态归类，不会当成可立即重试的普通失败。取令牌的请求没有做这个转换。
- **沙箱接口地址可以直接填。** `FEMA_BEISEN_BASE_URL` 设成沙箱域名即可，不用改代码；但沙箱要购买 PaaS，不能当作默认的联调方案。
- **自托管用户要登记出口 IP。** 授信 IP 是可选项，但很多租户会开。平台所在机器的出口 IP 变了（换云、换节点），北森会返回 403，要让运维记得去开放平台后台更新，动态 IP 的做法是配出口 IP 段。
- **升级公告对现有连接器没有影响。** 连接器代码里没有传 `enableTranslate`，也没有读 `translateProperties`。以后加需要字段翻译文本的动作时，要用官方数据源接口。
