# 国内厂商与生态：集成平台拆解

调研时间 2026-10-01。范围是飞书集成平台 AnyCross、钉钉（连接平台、宜搭集成&自动化、酷应用）、企业微信、腾讯轻联、华为云 ROMA Connect（含开天集成工作台 MSSI）、用友 YonLinker、金蝶、集简云、简道云、明道云、普元、东方通。AnyCross 业务集成的页面和交互已经写在 [../anycross-reference.md](../anycross-reference.md)，这里不重复，只补身份集成、本地代理、方案市场、连接器深度和运维细节。

**证据与可信度**

- 一手：各家帮助中心正文；飞书、企业微信的开放接口文档；AnyCross 公开接口返回的方案市场和连接器操作清单（`/webapi/market/*`、`/webapi/help_center/*`，需带页面下发的 CSRF 令牌）；AnyCross 控制台前端包里的界面文案。
- 二手：阿里云开发者社区的产品介绍文章、阿里云 IDaaS 文档里转述的企业微信规则、本仓库接北森时的实测记录。
- 缺口：检索额度中途用完。G2、知乎、V2EX 上没有查到可引用的第三方评价帖子；金蝶云苍穹集成平台、用友数据集成的操作界面要登录，未查到。标「推断」的是根据证据推出来的结论，不是原文。

## 一页结论

1. **国产集成的交付单元是「方案」，不是单条工作流。** AnyCross 的集成方案由项目生成，带资源清单、由变量生成的安装向导、安装检查项，能灰度、审核、定价，由服务商上架收费；用友按人力、费控、司库等领域打「集成资产包」。客户买的是「装上就能跑的一套东西 + 实施服务」。
2. **连国产系统，难点在对象模型、网络位置和对方的权限政策，不在协议。** 金蝶是「单据 × 操作」矩阵（AnyCross 的云星空连接器有 215 个操作）；用友 U8 要在 U8 侧配插件事件；泛微、致远、蓝凌在内网，要装本地代理甚至在本地跑一段程序；企业微信在 2022 年两次收紧通讯录接口；飞书写通讯录受「通讯录权限范围」约束。
3. **权限开通是跨人的交接。** 飞书事件订阅要到开发者后台手工做五步；钉钉通讯录连接器只有组织管理员能用；企业微信的通讯录同步只有主管理员能进。集成工程师自己开不了这些权限。
4. **运维面普遍薄弱。** 没有一家能按业务键（工号）查运行；重试多数不管幂等，宜搭直接在文档里写「重试可能产生无效数据，请自行承担风险」；日志多保留 30 天，最长的简道云 6 个月，而网络安全法要求网络日志留存不少于六个月。
5. **搭建范式有三类。** 表单驱动（宜搭、简道云、明道云：主流程在表单里，集成是表单事件之后的动作）；瀑布流画布加表单式映射（AnyCross、简道云、集简云、MSSI）；Mule 式消息编排（腾讯轻联、用友集成总线：payload、Choice、Try-Catch），后者只面向开发者。
6. **SaaS 平台伸进内网是常态，信创要求每一层都可替换。** AnyCross、腾讯轻联、用友、华为都要在客户内网装代理或网关；明道云的私有部署文档按数据库、消息队列、缓存、Web 服务器、对象存储逐层列出国产替代品；AnyCross 的本地代理只写了 x86。
7. **AI 目前停在两件事上：流程里的 AI 节点（大模型、AI 条件、OCR、发票识别），以及把集成能力开放成 MCP。** 公开文档里没有一家能用 AI 帮人搭集成或定位失败。

## 1. 核心对象模型

**飞书 AnyCross**（业务集成见 reference）

- 本地代理服务：宿主机（一台服务器一个）→ 工具箱（运维程序）→ 代理。代理分两种：数据通道代理（转发 SQL、HTTP，也是其他代理的通道）和连接器本地代理（例如泛微需要在本地执行一段程序、SAP 需要一个 jar 包）。代理组成代理集群，两个以上数据通道代理算高可用集群。[本地代理服务介绍](https://anycross.feishu.cn/documentation/platform/on-prem-intro)
- 身份集成：公开文档只有「应用单点登录」（OIDC、OAuth 2.0、SAML 2.0，回调地址必须逐字匹配，不支持单点登出）和「企业自定义身份源」。[配置应用单点登录](https://anycross.feishu.cn/documentation/platform/configure-sso)
- 前端包里还留着一整套「身份目录集成」界面文案，公开文档未收录（[auth 前端包](https://lf6-cdn2-tos.bytegoofy.com/gftar/anycross/microfe/auth/1.0.0.771/cn/index.js)；新版身份模块的[前端包](https://lf6-cdn2-tos.bytegoofy.com/gftar/anycross/microfe/identity/1.0.0.323/cn/index.js)只剩单点登录和身份源页面）：
  - 「统一身份目录」是平台侧的人员底表；每个来源建一个「身份目录」，先选「目录类型」。
  - 「目录属性」要指定主键，可勾选唯一性校验和存在性校验。
  - 字段的「映射关系」三选一：不进行映射、映射到、映射且作为用户关联唯一键；后者必须有且只能配给一个字段。
  - 「采集任务」配开始时间、截止时间和 cron；来源在内网时必须选一个代理集群。
  - 统计口径：需同步的变更行数、同步成功行数、同步错误行数；历史数据有「冲突」和「校验不通过」两种状态。
  - 卖点写的是「告别跨系统对接过程中复杂的用户身份转换操作」。
- 集成方案（同一前端包的文案，方案市场接口仍在用）：方案「基于项目生成」，包含资源清单、安装向导（「配置项由变量生成」，按字段类型生成表单控件）、安装检查项清单、可预览的安装向导；版本有灰度和全量，发布要审核，有可见范围、获取方式和价格。
- 服务商：服务订单（客户企业编码、服务经理、服务成员、有效期）→ 客户管理员签约 → 服务人员成为客户租户的外部协作者，在「服务商模式」下建的资源归客户。[服务订单和服务商模式](https://anycross.feishu.cn/documentation/platform/service-order-isp-mode)

**钉钉**

- 连接平台：连接器是「触发事件 + 执行动作」的集合。连接流分两种：业务流程由事件触发、自动执行；集成流程是动作集合，可以被业务流程调用，也可以当 API 用。企业接入的东西统称「连接资产」，第三方应用调用前要逐个授权。（[钉钉连接平台介绍](https://developer.aliyun.com/article/992334)；[官方 Quick Start](https://github.com/open-dingtalk/dingtalk-connect-integration)）
- 底层是阿里云计算巢 AppFlow：连接流「发布后无法编辑」，要改只能建新版本。[创建连接流](https://help.aliyun.com/zh/compute-nest/create-a-connection-flow)
- 宜搭：应用 → 表单 → 集成&自动化。触发类型有表单事件、定时、应用事件、手动，Webhook 标为即将推出；节点有数据、人工、消息、卡片、分支、循环、连接器、脚本。自定义连接器在「平台管理 → 连接器工厂」，分 HTTP 和 FaaS 两种。[集成&自动化简介](https://help.dingtalk.io/zh/yida/integration/gqmveiswrxkgxu9s)
- 酷应用：把应用拆成碎片组件，嵌进单聊、群聊、日程、文档；互动卡片能在卡片里点按钮完成操作，支持「千人千面」。[酷应用总体介绍](https://developer.aliyun.com/article/951100)

**腾讯轻联**：项目 → 应用 → 流程。有触发能力的是主流，其余只能被 Flow Reference 引用为子流；消息模型是 payload、attribute、variable、error。「环境」指运行集群，分共享环境和独立环境，不是测试和生产。[流程配置](https://cloud.tencent.com/document/product/1270/76471)、[环境管理](https://cloud.tencent.com/document/product/1270/76459)

**华为云 ROMA Connect**

- 集成应用是同一实例内的资源隔离单位：数据源、API、Topic、设备都必须归属某个集成应用。它带一对 Key/Secret 用于访问认证，可以授权给同账号下的其他 IAM 用户。[创建集成应用](https://support.huaweicloud.com/usermanual-roma/create-application.html)
- 数据集成任务分普通任务（定时或实时，单表到单表）和组合任务（CDC，多表到多表），实时任务支持断点续传。[数据集成](https://support.huaweicloud.com/usermanual-roma/fdi-ug-190429001.html)
- 组合应用由业务流、触发器、连接器、处理器、变量、函数表达式组成。[组合应用](https://support.huaweicloud.com/usermanual-roma/roma_03_5038.html)
- 开天集成工作台 MSSI 是另一条轻量产品线：连接器、连接、流（触发事件 + 执行动作）。

**用友 YonLinker**：由 API 网关、数据集成、集成总线（YSB）、主数据、混合云网关组成。

- 数据集成的对象是「集成对象」和「转换规则」。
- 集成总线的对象是环境、集成应用、集成流、连接配置。
- 预置的「集成资产包」按人力、税务、营销、采购、费控、司库、商旅、协同、招聘、项目分类。

来源：[数据集成](https://developer.yonyou.com/product/integrated/integrateddata)、[集成总线](https://developer.yonyou.com/product/integrated/bus)、[YonLinker](https://www.yonyou.com/subject/YonLinker)。

**金蝶**：云星空开放接口的对象是「表单 × 操作」，见第 6 节。金蝶天燕的企业信息集成是传统 ESB 加主数据。[企业信息集成](https://www.kingdee.com/solutions/eii.html) 金蝶云苍穹集成平台的对象模型未查到。

**简道云、明道云、集简云**

- 简道云：表单 → 智能助手 Pro，由触发节点和执行节点组成。
- 明道云：集成中心里，连接（鉴权 + 连接参数）→ API（输入参数、请求、代码块、输出参数）→ 授权给应用。[API 集成](https://help.mingdao.com/integration/api)
- 集简云：数据流程 = 触发应用 + 执行应用，凭证叫「应用账户」。[如何创建数据流程](https://www.jijyun.cn/help/detail/2)

**传统 ESB**：对象是「服务」，生命周期是注册、部署、运行、审计、注销；配套协议转换、消息转换、路由、热更新。[普元 ESB](https://www.primeton.com/products/esb)、[东方通 TongESB](https://www.tongtech.com/pctype/45.html)

**小结**：SaaS 系集成平台的顶层容器都是「项目」或「应用」，权限和凭证挂在上面；ERP 厂商把「集成对象」「集成方案」做成一等对象；只有 AnyCross 做过「身份」这种领域对象，而且公开面已经收回到单点登录。

## 2. 搭建体验

**从空白到第一条跑通**

- **宜搭（表单驱动，路径最短）**：应用设置 → 集成&自动化 → 新建（从空白或从模板）→ 填名称、选触发类型 → 鼠标移到连线上点 + → 连接器 → 钉钉官方 → 选执行动作并配置 → 保存 → 发布 → 提交一张真实表单验证。官方示例是「员工离职记录」表单提交后删除钉钉通讯录用户，操作者必须是钉钉组织管理员。[通讯录连接器](https://help.dingtalk.io/zh/yida/integration/ncdt7p3g2db6d11n)
- **钉钉 OA 审批连接器**：映射以表单控件为中心，入参一张表「填写以下控件的值获取数据」，出参一张表「获取的数据填充到以下控件」；执行动作的参数可以导入 JSON 生成。[钉钉连接平台实践](https://developer.aliyun.com/article/993629)
- **AnyCross 的事件触发要在飞书开发者后台手工做五步**（[订阅事件](https://anycross.feishu.cn/documentation/faq/Subscribe_events)）：
  1. 给应用开权限。
  2. 填请求地址，用 AnyCross 接收时不能开启事件加密。
  3. 添加事件。
  4. 多维表格这类事件还要先跑一次工作流来「订阅资源」。
  5. 发布应用。

  一个应用只能设一个请求地址，两个工作流要订阅同一个应用的不同事件时，官方建议把第一个触发器的地址拷到第二个；只有触发器的工作流不能发布。
- **腾讯轻联**：画布 Trigger 区放 Scheduler → 加 Database 连接器，查询有单表、多表、SQL 三种模式 → 中间插 Mapper 拖拽映射 → 目标库「批量插入」→「调度运行」。Mapper 组件现已标记弃用，映射改为直接写在各连接器的参数框里，可以用代码或表达式。[数据集成入门](https://cloud.tencent.com/document/product/1270/62797)、[数据映射（已弃用）](https://cloud.tencent.com/document/product/1270/100958)
- **华为 MSSI**：我的流 → 创建流 → 选触发事件、配参数 → 加执行动作（可拖拽排序）→ 右上角「检查」→「保存并测试」。（[创建流](https://support.huaweicloud.com/usermanual-mssi/mssi_02_0023.html)）
  - 节点上有「调测节点」，生成样本数据。
  - 映射方式有「智能映射」（把上一步的响应自动映射到当前节点）、动态面板（全局参数、函数、变量）和手动输入。
  - 高级配置有四项：「敏感信息配置」（不记录出入参日志）、「策略配置」（重试次数、超时）、「数据空值策略」（取不到值时用默认值）、「业务配置项」（把节点参数暴露到配置管理页）。
- **华为 ROMA 组合应用**：调试模式下点节点就能加断点，可以单步运行、运行到下一断点、运行到结束；停在断点时显示进入该节点的「属性」和「载荷」；单节点最多停留 60 秒，触发器、并行和分支节点不能加断点。[调试组合应用](https://support.huaweicloud.com/usermanual-roma/roma_03_5060.html)
- **用友集成总线的开发流程有十步**：新建环境（配置集成引擎）→ 新建集成应用 → 设计集成流 → 选环境部署 → 测试 → 监控运维 → 正式使用 → 测试生产环境 → 把连接配置调整为生产环境的 → 导入生产环境。数据集成走「集成方案设计」：对象映射，加筛选、排序、前置任务关联，再加「多种翻译机制」。
- **明道云**（[API 集成](https://help.mingdao.com/integration/api)）：
  1. 集成中心 → 我的连接 → 自定义连接。
  2. 选鉴权方式：API Key、Basic、OAuth 2.0 客户端凭证、OAuth 2.0 授权码。
  3. 填连接参数，可以勾选隐藏；隐藏后只能修改、不能再显示。
  4. API 管理里配输入参数、请求和代码块（JS 或 Python）→「测试 API」→ 用测试返回体生成输出参数 → 发布。
  5. 授权给应用，在工作表字段或工作流节点里使用。

  预置 API 从 API 库安装，连接认证自动配好，只填参数值。
- **集简云**：选触发应用 → 选账户（可当场「添加新账户」，自动弹出该应用的帮助文档和授权视频）→ 选执行应用 → 字段匹配 → 保存后自动执行。[如何添加应用账户](https://www.jijyun.cn/help/detail/96)

**每一步怎么测**：只有 ROMA 做到断点加单步。MSSI 和明道云能对单个节点或单个 API 拿到样本数据。其他产品基本靠「真跑一次」：AppFlow 的「运行一次」、腾讯的「调度运行」、宜搭提交一张真实表单；AnyCross 要么手写调试出参 JSON，要么用网址触发器的「获取数据并预览」（见 reference）。

**复用**：

- AnyCross：方案、模板，节点能跨工作流、跨项目复制粘贴。
- 腾讯轻联：子流（Flow Reference）。
- 明道云：组织库，管理员把连接放进去，成员申请使用。
- 用友：集成资产包。
- 华为：资产中心。

## 3. 人事、财务、OA 的预置方案怎么做

AnyCross 方案市场共 135 个方案，按分类：团队协作 31、人力资源 30、电商物流 21、项目管理 14、审批协同 14，其余较少。（[方案接口](https://anycross.feishu.cn/webapi/market/solutions)，2026-10-01 取数）

- **人事**：
  - 付费：飞书人事 → 泛微 OA、飞书人事 → 致远 OA 的部门、职务、职级、人员同步；飞书招聘 ↔ 北森、薪人薪事的预入职。
  - 免费：北森请假 → 飞书日历；飞书通讯录 → 多维表格。
  - 市场里没有「北森 → 飞书通讯录开通账号」的方案（推断：飞书在推自己的飞书人事）。
- **OA**：致远、蓝凌 EKP15、泛微 E8 的审批待办进飞书审批中心，都是付费方案。用到的连接器名字直接叫「内网致远」「内网蓝凌」「内网泛微 E8」，靠本地代理。
- **财务**：金蝶云星空（飞书审批通过后生成付款单、凭证，物料同步）、用友 U8（收款提醒、审批通过建入库单和付款单）。很多由服务商上架并收费，例如「轮动」「花生加科技」「百里挑一」「航翼」。
- **其他厂商的做法**：
  - 用友的资产包按业务领域打包。
  - 钉钉、宜搭用「通讯录」「智能人事」「考勤」「OA 审批」官方连接器加表单模板来做，例如请假审批写考勤、待入职写智能人事。[官方连接器](https://help.dingtalk.io/zh/yida/integration/qaghpy2gu779gi1l)
  - 简道云、明道云的「方案」是整套应用模板（CRM、SRM、进销存），人事场景用智能助手 Pro 做「入转调离」。[智能助手 Pro](https://hc.jiandaoyun.com/doc/18443)

**结论**：国内的「方案」= 工作流 + 前置配置 + 实施服务，付费方案和服务商是常态。OA 方案的主体是「待办进 IM」，属于主流程和审批，按决定 000039 越界；人事方案的主体是组织人员同步，正是我们的主线。

## 5. 生命周期

- **环境**：
  - AnyCross 用配置组切换变量值。
  - 腾讯轻联用「授权配置分组」：同一个连接在不同分组里配不同账号，发布时选分组，等于一键换成测试或正式账号；改连接配置要重启关联的应用，会瞬时中断。[授权配置](https://cloud.tencent.com/document/product/1270/76465)

  - AnyCross 发布即启用、覆盖正在运行的版本；AppFlow 发布后不能改。

  - AnyCross 方案有灰度和全量。
  - 一键回滚：AnyCross 没有（reference），其他家未查到。
- **依赖和影响**：
  - AnyCross 做得最细：删除代理或代理集群前，列出「可能导致凭证不可用」「可能导致 SSO 应用不可用」；删除变量提示「引用此变量的入参将无法找到对应值」；发布时检测应用还缺哪些事件订阅，以及「发布后将会覆盖已有的事件订阅地址」（前端文案）。[管理本地代理服务](https://anycross.feishu.cn/documentation/platform/manage-on-prem-service)

## 8. 连接器策略与国产系统的连接难点

**数量与深度**

- **连接器数量**：
  - AnyCross 集成市场公开目录 136 个（[接口](https://anycross.feishu.cn/webapi/market/connectors)）。
  - 宜搭官方连接器覆盖 24 个钉钉应用。
  - ROMA 写 100+ 连接器、200+ 模板。
  - 集简云 1007 个应用。[应用列表](https://www.jijyun.cn/apps/)
  - 明道云 API 库预置 200 多种 API。
- **深度差别很大**，以 AnyCross 自己的连接器为例（操作清单接口 `/webapi/help_center/connectors/{id}/operations`）：
  - 北森组织员工 v1.8：20 个操作、0 个触发器。员工变动只能靠「根据时间窗滚动查询变动的员工与单条任职信息」轮询。
  - 金蝶云星空 v1.17：215 个操作、0 个触发器。操作是「单据 × 操作」：付款单、收款单、物料、客户、供应商、采购订单、销售订单……乘以暂存、保存、提交、审核、反审核、撤销、下推、作废、禁用、分配。
  - 用友 U8：4 个操作、2 个触发器。触发器要在 U8「API 资源管理器」里配插件事件（保存后事件、审核后事件）。

**自定义连接器与生态**

- 腾讯：连接器的操作和触发器本身用流程在画布上画；有自定义数据类型（可「上传 JSON」自动识别）；文档根据配置自动生成；测试用例不过不能发布。
- 宜搭 HTTP 连接器的鉴权有六种：无、Basic、API Key、阿里云 API 网关、钉钉开放平台（自动注入 access_token）、钉钉零信任网关。测试时选鉴权账号，再填测试参数。[HTTP 连接器](https://help.dingtalk.io/zh/yida/platform-admin/zbq17y)
- MSSI 的执行动作可以是 API、函数或流。
- 用友有「连接器共建机制」。
- 集简云开放平台免费上架，人工测试后全网发布，也能先邀请指定企业试用。[开放平台](https://www.jijyun.cn/open.html)
- 钉钉的第三方连接器要先「订阅」才出现。
- 从 OpenAPI 或文档自动生成连接器：未查到；普元的「AI 自动解析接口」只见于营销页。

**国产系统的连接难点**（证据）

- **北森**（本仓库实测，见 [building-connectors.md](../../../brain/knowledge/connectors-engine/building-connectors.md)）：
  - 开放文档要登录才能看。
  - `/token` 接口的字段是 `app_key`；失败时也返回 HTTP 200，错误放在 body 里。
  - 业务接口返回 `{code, message, data}`，成功码没有文档。
  - 时间窗查询一次返回 100 行加 `scrollId`，必须在一次轮询里翻完；时间戳不带时区。
  - 模块名只能靠网关返回码试探，绩效模块找不到。
- **用友**：
  - U8 的事件要在 U8 侧装插件。
  - 数据集成要「翻译」档案（推断：部门、人员、科目在两边编码不同，要按对照表转换），并且要设置「前置任务」，即先同步被引用的档案。
- **金蝶**：
  - 写单据不是一次 POST，要决定停在暂存、保存还是已审核（推断，依据是操作清单）。
  - 钉钉社区有人问「钉钉有没有连接器登录金蝶云星空查询数据的开发指南」，0 条人工回答。[提问](https://developer.aliyun.com/ask/583330)
- **泛微、致远、蓝凌**：多数部署在内网。AnyCross 要先装数据通道代理，再装连接器本地代理，泛微还「需要在本地执行一段程序代码」。
- **飞书**（[创建用户](https://open.feishu.cn/document/server-docs/contact-v3/user/create)）：
  - 创建用户时，所有部门都必须在应用的「通讯录权限范围」内（错误 40004），改了范围要发布应用才生效。
  - 支持 `client_token` 幂等，频率上限 1000 次/分钟、50 次/秒。
  - 错误码里有「部分成功」：44054–44056 是用户已创建，但工作城市或职务没写进去。
  - 有「要等 24 小时」的：44004；还有「一个手机号或邮箱一天只能加入三个租户」（44009）和席位上限（41007、41008、44023）。
- **企业微信**（[企业微信接口文档镜像](https://s.apifox.cn/apidoc/docs-site/406014/doc-417869)、[IDaaS 对接说明](https://help.aliyun.com/zh/idaas/eiam/user-guide/bind-idaas-to-wecom)）：
  - 2022-06-20 起，新开启的通讯录同步必须配企业可信 IP，只能是企业自有服务器的 IP，不能是第三方服务商的。
  - 2022-08-15 起，用「通讯录同步 secret」读接口或收变更事件，只返回 ID，不再返回姓名、手机号、部门名。
  - 自建应用、代开发应用、第三方应用只能读、不能写，且只能读可见范围内的通讯录。
  - 不支持查询增量数据，IDaaS 的做法是每天凌晨全量同步。
- **钉钉**（[连接器节点 FAQ](https://help.dingtalk.io/zh/yida/integration/rhg7w5n7la2t69bv)、[宜搭限流](https://help.dingtalk.io/zh/yida/developer-features/wae8oddztfq167ly)）：
  - 通讯录「创建用户」报 40103 的情况有三种：员工已在另一家认证企业、对方开了「团队添加我时需要验证」、当天删除后又重新邀请。
  - 宜搭的数据过滤只能按排序取前 100 条。
  - 宜搭调用钉钉每个接口最高 40 次/秒。

- **华为**：产品页写了 MCP 服务托管；MSSI 的「智能映射」没写明是规则还是模型。
- **集简云**：语聚 AI、集简云 MCP（「连接 AI 大模型与上千款软件」）。
- **只见于营销页**：普元「AI 集成智能体：自动解析接口、智能运维预警」，用友「通过 AI 技术与资产沉淀降低集成风险」，都没有操作文档。
- **未查到**：腾讯轻联、简道云、明道云集成部分的 AI 搭建或诊断能力。

## 10. 用户的称赞与抱怨

第三方评价未查到：G2、Capterra 基本不收录这些产品；知乎和 V2EX 的检索额度用完了。下面是能核实的「抱怨证据」，来自厂商文档自己承认的限制和社区提问。用户称赞同样未查到，文档里做得好的地方放在下一节。

1. **重试不安全，风险推给用户**：宜搭运行日志页的警告。
2. **推送失败不补发**：宜搭集成中心 FAQ，「暂时没有做重试等相关逻辑」。
3. **日志只留 30 天**：腾讯轻联要查更早的得提工单；AnyCross 也只能查 30 天。
4. **改表单会静默弄坏流程**：宜搭 FAQ 里的组件单选改多选。
5. **一次最多取 100 条**：宜搭数据过滤。
6. **一个飞书应用只能配一个事件地址**：要在工作流之间拷贝回调地址（AnyCross FAQ）。
7. **平台政策变化打断集成**：企业微信 2022 年两次收紧通讯录接口。
8. **改了配置，重试却按旧版本执行**：这是简道云有意的设计，但用户容易困惑。
9. **按版本卡连接器数量**：宜搭免费版每个应用 1 个集成&自动化，组织内 1 个自定义连接器。
10. **国产 ERP 接入没有现成答案**：钉钉社区「连接器接金蝶云星空」无人回答；「钉钉连接器怎么在本地调试」只有零散的变通办法。[提问](https://developer.aliyun.com/ask/558288)

## 11. 对我们的启示

### 11.1 值得借鉴的具体设计

1. **「对方后台待办单」**（来源：AnyCross 订阅事件的五步手工配置、宜搭「仅组织管理员」、企业微信「仅主管理员可进通讯录同步」）。
   - 位置：连接向导第二步。
   - 布局：右侧卡片，标题「需要飞书管理员完成」，逐条列出：菜单路径（开发者后台 › 应用详情 › 权限管理 › 数据权限）、要开的权限名、通讯录权限范围要覆盖的部门（从映射表的目标部门自动算出）、要添加的事件、可复制的请求地址；最后一条是「发布应用版本」。
   - 每条右侧一个状态：未检查、已就绪、缺失；底部「重新检查」。
   - 卡片顶部「复制为消息」生成一段文字，发给对方管理员。
   - 为什么：权限开通是跨人交接，第一次上线最常卡在这里，而集成工程师自己做不了。
2. **发布前的「对方系统就绪」检查**（来源：AnyCross 发布时检测缺失的事件订阅和「将覆盖已有订阅地址」；飞书 40004）。
   - 发布弹窗里加一节，三行：事件订阅、通讯录权限范围（列出不在范围内的目标部门，例如「深圳研发中心/测试组」）、限流。
   - 有红项时「发布」置灰；黄项允许带确认发布。
   - 为什么：能在设计期发现的错误不留到运行时（备忘的可靠性原则）。
3. **一个连接一个入站地址，平台内部分发**（来源：AnyCross 一个应用只能配一个请求地址的变通办法）。
   - 连接详情页显示唯一的「事件接收地址」和「订阅此连接事件的工作流」列表；新增一条订阅不需要回飞书后台改地址。
   - 为什么：把对方的平台限制吸收在平台里，而不是写进 FAQ。
4. **方案 = 清单 + 由声明生成的安装向导 + 安装检查项**（来源：AnyCross 集成方案、用友资产包）。
   - 方案详情页：左栏是方案包含的资源（工作流、映射表、对账规则、告警）；右栏「安装前要准备的」检查项（两端连接、对方后台待办单）。
   - 安装向导的步骤由方案声明的配置项生成，不手写：连接、部门映射、起点、通知群。
   - 最后一步「安装结果」列出新建的资源和首次对账结果。
   - 为什么：这是国内客户和实施方习惯的交付单元，也是决定 000041 的落点。
5. **错误类型四分类，每类对应一个按钮**（来源：飞书错误码表）。
   - 问题详情顶部是错误类型标签：
     - 需要授权（40004），按钮「去处理对方后台待办单」。
     - 数据冲突要人判断（41001 手机号已存在），按钮「按手机号查飞书用户」。
     - 稍后自动重试（44004，显示「将于 24 小时后重试」）。
     - 部分成功（44054，账号已建、职务未写入），按钮「只补职务」。
   - 为什么：国内平台普遍只给原始报错，值班的人还得自己翻文档。
6. **运行详情 = 着色画布 + 运行时版本 + 复制诊断信息**（来源：简道云执行日志、ROMA 断点载荷）。
   - 运行详情页主体是只读画布：绿成功、红失败、蓝执行中、灰未执行。
   - 顶部写「运行时版本 v5（当前最新 v6）」。
   - 右栏是选中节点的输入和输出。
   - 「复制诊断信息」把运行 ID、版本、错误码、对方返回的请求 ID（飞书 `X-Request-Id`）打成一段文字，给厂商提工单用。
7. **重放对话框写清三件事**（来源：宜搭节点重试和流程重试、简道云版本钉住）。
   - 用哪个版本：运行时版本或最新版本，二选一，默认最新并提示差异。
   - 读哪份数据：「按工号重新读取北森最新状态」（决定 000042）。
   - 哪些步骤跳过：「发送入职通知：不幂等，上次已成功，跳过」。
   - 为什么：别人把这件事写成「请自行承担风险」，我们应该把它做成确定的行为。
8. **告警的免打扰窗口和发送上限**（来源：宜搭免打扰时长、腾讯持续 N 个周期和重复频率）。
   - 告警策略页每条规则有「同一问题在 X 分钟内不重复通知」和「每小时最多 N 条」两个字段。
   - 规则列表显示「本小时已发 12/30」。
   - 超上限后合并成一条摘要。
9. **实施方临时账号**（来源：AnyCross 服务商模式的自托管版）。
   - 成员管理里加「外部实施人员」。
   - 新建时必填有效期、可访问的项目、负责人；到期自动停用。
   - 到期前 7 天通知负责人，停用时生成交接单：此人建过、改过的资源和未处理的问题。
   - 为什么：国内集成大多由实施方交付，第三版原型只考虑了值班。
10. **「网络与信创」体检页**（来源：AnyCross 预检脚本和域名白名单、企业微信可信 IP、明道云信创目录）。
    - 位置：管理后台「系统」下。
    - 出网检查：按连接器列出要访问的域名，从工作节点逐个测连通性；显示「当前出口 IP」并提示「请填到企业微信企业可信 IP」。
    - 运行环境：CPU 架构、操作系统、数据库及版本，每项标「已验证」或「未验证」。
11. **节点级「取不到值时」和「敏感」开关，加智能映射**（来源：MSSI 数据空值策略、敏感信息配置、智能映射）。
    - 映射表格里每个目标字段末尾一个下拉：报错、用默认值、跳过。
    - 节点参数页有「出入参不写日志」开关。
    - 「智能映射」按钮先按字段名和类型匹配，再给 AI 建议（备忘已定：AI 建议逐条确认）。
12. **人员对照表作为同步方案的一部分**（来源：AnyCross 身份目录的「映射且作为用户关联唯一键」，简道云「改成员账号会丢权限」）。
    - 方案自动建一张「人员对照」：工号 ↔ 飞书 user_id ↔ 企业微信 userid，记录每次变化。
    - 对方修改账号 ID 时进问题中心，而不是悄悄失去关联。
    - 为什么：「身份转换」是 AnyCross 单独做身份目录的原因；决定 000041 不做身份产品，但这张对照表不能少。
13. **前置对象**（来源：用友「前置任务关联」）。
    - 方案声明「部门先于人员」。
    - 部门映射缺失或目标部门不存在时，人员同步停在「等待前置」，不算失败。
    - 补齐部门后自动继续。
14. **连接器完成度报告**（来源：腾讯连接器「完成度校验报告」，测试用例不过不能发布）。
    - 连接器开发页的发布前报告，就是第三版的七项深度清单自动打分：红项挡发布，黄项可带警告发布。

### 11.2 反面教材

- 发布即覆盖运行、没有回滚（AnyCross）；另一个极端是发布后不能改（AppFlow）。
- 重试不管幂等，把风险写进文档推给用户（宜搭）；推送失败不补发（宜搭集成中心）。
- 日志保留 30 天、查更早要提工单（腾讯、AnyCross），既不符合网络安全法的六个月，也回答不了「三个月前那个人怎么没账号」。
- 平台限制藏在 FAQ 里：取前 100 条、自动触发 3 层、改表单后条件静默失效（宜搭）。
- 凭证归个人，离职要管理员批量转移（AnyCross）。
- 先把映射做成独立组件，后来又弃用（腾讯 Mapper）。映射应该一开始就长在节点参数里。
- Mule 式 `msg.payload` 编排（腾讯、用友总线）对实施人员和值班的人都不友好。
- AI 走申请制、按次计费，并绑定厂商云上的模型（AnyCross）。
- 平台只认一种即时通讯工具，不支持私有化版本（简道云、AnyCross）。
- 本地代理只支持 x86（AnyCross），信创环境装不上。

### 11.3 对我们定位的特别含义

- **自托管是优势，不只是负担。**
  - 企业微信要求可信 IP 是企业自有服务器，同一个 IP 服务多家企业就会被当成服务商。SaaS 平台在这里天然吃亏，部署在客户机房的平台天然合规。
  - 方向也反过来：别人要把代理伸进内网，我们要从内网出网去连飞书和北森。所以出网体检、域名清单、出口 IP 是一等界面。
  - 信创要求每一层都可替换：先做 ARM64 镜像，验证 PostgreSQL 系国产库（openGauss、瀚高、人大金仓），再找 Redis 的替代品。
- **中国企业。**
  - 方案和实施方是市场结构，不是附属功能：方案向导、实施方临时账号、交接单都要有。
  - 术语沿用客户熟悉的：连接、方案、映射表（可以在帮助里注明「也叫对照表、翻译」）、可见范围、通讯录权限范围。
- **辅助流程。**
  - OA「待办进 IM」占了 AnyCross 审批类方案的大头，按决定 000039 不做。
  - 人员同步是国内厂商普遍做得浅的地方：AnyCross 市场里没有北森到飞书开通账号的方案；企业微信不支持查增量，只能定期全量比对，正好印证对账（决定 000040）和期望状态同步（决定 000042）。
  - 飞书的部分成功错误码、`client_token` 也支持「确保存在」的语义。
- **AI 优先。** 国内对手还停在「AI 节点 + MCP」，「AI 帮你搭、帮你修」是空位。三个具体落点：
  - 从对方文档生成连接器草稿：北森文档要登录，可以让客户上传文档或接口集合，生成后用深度清单校验。
  - 按两端字段和真实样本建议映射。
  - 按错误码表和对方返回体给出四分类和修复动作。

  模型必须能配成客户自己的端点（DeepSeek、通义、豆包这类），不能走申请制和外部额度。
- **不止值班一个角色。** 证据显示，至少还有四个人的主界面要设计：
  - 对方系统管理员：拿到待办单的人。
  - 实施方：临时账号、方案安装。
  - 平台管理员：出网、信创、日志保留。
  - 业务方：HR 问「某人为什么没账号」时，按工号查到结论。
