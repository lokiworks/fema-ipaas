## Overview

Event Streaming forwards platform [audit events](/admin-guide/security/audit-logs/overview) to a webhook URL of your choice. The most common pattern is to point that webhook at a workflow inside FEMA Integration Platform — your workflow then routes each event to the channel you care about (Slack, Gmail, Microsoft Teams, custom HTTP, etc.).

Use it to react to workflow run failures, new sign-ins, project releases, or any other audit event with the alerting tool of your choice.

## Quick start

The fastest way to get going is the **Generate handler workflow** button in the New destination dialog. It builds a webhook-triggered workflow with one router branch per event you select, plus a nested branch for failed runs when you pick `workflow.run.finished`.

1. Open **Platform Admin → Event Streaming**.
2. Click **New Destination**, pick the events you want to handle, and click **Generate handler workflow**.
![Create event destination](/resources/screenshots/event-destination.png)
3. The workflow lands in your personal project with a webhook trigger and a router branch per selected event. Sample data is pre-baked so you can hit Test right away, you can add a router step under any event branch to check for specific projects/workflows ids.
![Event destination handler workflow](/resources/screenshots/event-destination-workflow.png)
4. Customize the branches with whatever connectors you like — Slack, Gmail, Microsoft Teams, custom HTTP, and so on.
5. Publish the workflow, then go back to the New destination dialog and click **Create** to save the destination.
6. Use the **Test webhook** dropdown in the dialog to fire a sample of any selected event and confirm the round-trip.

## Available events

You can subscribe a destination to any audit event — workflow lifecycle, run status, folder/connection changes, user activity, and platform admin actions. See the [Audit Log Events catalog](/admin-guide/security/audit-logs/overview#event-catalog) for the full list and per-event payload details.

## Use your own webhook URL

If you already have a webhook URL — or you want to point Event Streaming at a SIEM, data warehouse, or any other external system — you can skip the handler workflow and configure the destination by hand:

1. Go to **Platform Admin → Event Streaming**.
2. Click **New Destination**.
3. Select the **Events** you want to forward.
4. Paste your **Webhook URL** (must be a valid HTTPS endpoint).
5. Use the **Test webhook** dropdown to fire a sample payload for any selected event.
6. Click **Create** to save.

## Payload shape

Every event is delivered as an HTTP POST with a JSON body. The top-level fields are:

- `action` — the event name (for example `workflow.run.finished`).
- `data` — event-specific payload, including details like the workflow id, run id, status, or affected user.
- `id`, `created`, `updated` — event identifiers and timestamps.
- `platformId`, `projectId`, `userId` — context fields shared across all events.

## Requirements

- **Enterprise Edition**: Event Streaming requires an enterprise plan with Audit Logs enabled.
- **Platform admin**: only platform admins can configure destinations.
- **HTTPS endpoint**: webhook URLs must use HTTPS.
- **Publicly accessible**: external endpoints must be reachable from your FEMA Integration Platform server. Handler workflows on this same instance are delivered internally, so they work even when the instance is not publicly reachable (for example, behind an internal load balancer).

## Troubleshooting

- **Events not received**: for external endpoints, verify they are reachable from your server and return 2xx status codes. For a handler workflow on this instance, make sure the workflow is published and enabled.
- **Test fails**: check that your URL is valid and uses HTTPS.
- **Missing events**: make sure the event type is selected in your destination configuration.
