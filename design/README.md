# 集成平台交互高保真原型

一个可以直接点的高保真原型，覆盖除「数据集成」以外的全部页面。信息架构和交互照飞书集成平台（AnyCross，`anycross.feishu.cn`）来做，视觉沿用本仓库的设计系统（`.claude/skills/design`）：紫色主色、Inter + 苹方、中性灰、Lucide 图标。

第一版把 AnyCross 的页面和交互铺全；第二轮按 [research/product-brief.md](research/product-brief.md) 补齐产品能力：字段映射、运行可靠性、问题中心与告警、环境推广与审批、数据脱敏与保留、AI 生成与智能体、自托管运维。备忘里的七个关键场景都能在原型里从头走到尾，走法见下面「七个场景怎么走」。

调研依据见 [research/anycross-reference.md](research/anycross-reference.md)。

**这一版是主原型。** [v3/](v3/README.md) 是 2026-10-01 放弃的探索，只作参考。

## 怎么打开

直接双击 `index.html`，用 Chrome、Edge 或 Safari 打开即可。不需要构建，也不需要联网：React、htm、Lucide 和字体都放在本地的 `vendor/`、`fonts/` 里。

- 你在原型里做的修改（新建工作流、发布、改配置……）会存在浏览器的 localStorage 里，刷新后还在。隔了一段时间再打开，演示数据的时间会整体平移，「17 分钟前」这类相对时间不会越放越旧。
- 想恢复初始数据：点左下角头像 →「重置演示数据」。
- 深色模式：头像菜单 →「深色」。
- 全局搜索：`⌘K`（Windows 上是 `Ctrl+K`）。
- 交互式教程：左侧栏「教程」；帮助文档：左侧栏「文档」。

演示数据是一家虚构公司「星河科技」，当前登录的是平台负责人「林晓」。主项目「人事行政」开启了测试和生产两个环境，里面有 14 条工作流；另有研发效能、销售运营、财务共享三个只有生产环境的项目。几处故意的设置：

- 金蝶正式账套和 Salesforce 两个连接失效，用来演示问题中心、根因分析、重新授权和批量重跑。连接没修好之前重跑会被拦下；测试环境用的是金蝶测试账套，所以采购工作流在测试环境能调通。
- 「报销票据识别入表」v6 已在测试环境验证，等林晓审批推广到生产。
- 「IT 服务台智能体」有一次运行在等人工确认：智能体想在 Jira 建工单。
- 陈思远正在编辑「离职交接与资产回收提醒」，其他人打开只能查看。
- 接入了两个外部 MCP 服务器：内部知识库（正常）和金蝶助手（连接超时）。
- 安装时跳过了邮件服务和对象存储，所以邮件渠道显示为未启用，文件存在本地目录。
- 林晓在「财务共享」里只有「可查看」权限，用来演示只读状态；在研发效能、销售运营里是「可编辑」，可以对比项目所有者和编辑者能做的事。

## 七个场景怎么走

1. **一句话生成工作流**：在首页输入框写「员工入职后在飞书建档，按部门开通账号并通知 HR 群」，回车。首发主线的几句也能规划：「北森有员工入职时，在飞书按部门开通账号，并在 HR 群发欢迎消息」「北森员工离职后，暂停他的飞书账号，并通知 IT 回收电脑」「员工在北森调岗后，同步更新飞书里的部门和直属上级」。AI 给出步骤、需要的连接和待确认的问题，回答问题会实时改变计划；生成后进入编辑器，节点标着「待确认」，对象类入参的字段映射已经预填，逐个检查后确认。描述太模糊时 AI 会要求补充，不会乱猜。
2. **字段映射**：打开 `#/integration/p1/wf/wf_purchase?mode=edit`，点「保存采购订单」→「入参」。单据数据用的是「映射」：采购明细逐项映射成金蝶明细行，物料编码经过「物料编码对照」表转换。「展开编辑」能看到每一步转换的中间值；「AI 自动映射」给出建议和置信度，需要逐条确认。映射表在项目侧栏「映射表」，被工作流引用时不能删除。
3. **50 条失败，5 分钟定位**：左侧栏「问题」→ 金蝶连接的问题 → 看 AI 根因分析 →「重新授权连接」→ 回到问题 →「从失败节点批量重跑」，前面成功的节点沿用原结果 →「标记已解决」。「告警策略」里能看到聚合窗口、静默时段、升级规则和通知渠道。
4. **安全地推到生产**：打开 `#/integration/p1/releases/rel_ocr6`，看版本差异、上线前检查和测试环境的运行记录，然后批准。也可以在编辑器里改完「发布到测试」，再「推广到生产」。「版本管理」里可以对比任意两个版本、回滚到历史版本。打开「离职交接与资产回收提醒」能看到编辑锁。
5. **合规地保存运行数据**：管理后台「数据与隐私」设置保留期、脱敏规则（可以写自定义正则并实时预览）、个人数据删除。运行日志里被脱敏的字段可以「查看原文」，需要有权限、填写原因，并写入审计。编辑器里节点的「出参」页可以把出参标为敏感。
6. **自托管从零到可用**：`#/setup` 回放安装向导（环境检查 → 管理员 → 组织 → 可选服务 → 完成），可选服务跳过后会写清楚影响。管理后台「系统与升级」看新版本、破坏性变更、升级前检查和复制即用的升级命令；「备份与恢复」可以立即备份，也可以走恢复预检。
7. **MCP 双向打通**：连接器市场「接入 MCP 服务器」，连接测试会给出真实的失败原因。打开 `#/integration/p1/wf/wf_itdesk?mode=edit` 看「AI 智能体」节点的工具和护栏；在运行日志 `#/logs?run=run_agent_wait01` 里批准或拒绝它的建单请求。原有的「MCP 服务」把连接器和工作流开放给外部 AI 助手。

## 值得点一点的交互

编辑器（`#/integration/p1/wf/wf_purchase?mode=edit`）：

- 点连线上的 +，按「逻辑 / 助手 / 应用 / AI」选节点；搜索框同时匹配连接器名和操作名（例如搜「发起审批」）。左侧工具条「连接器」面板里的节点和操作可以直接拖到连线上的 +，外部 MCP 服务器也在「应用」里。
- 点节点打开右侧浮动面板：操作 / 连接 / 入参 / 出参 / 错误处理，有错的 Tab 带红点。节点被面板挡住时画布会自动挪开。
- 每个节点有固定的 ID（例如 `feishu-1`），创建后不随位置变化。
- 入参左边的小圆圈按住拖到画布上的上游节点，松开后选一个出参字段，会以「胶囊」写进参数；点胶囊可以复制或删除这一处引用。只能引用上游节点，引用失效时胶囊变成「已失效的引用」，校验面板会报错。
- 对象类入参可以在「映射」和「JSON」之间切换，切换不丢内容。映射按目标字段逐个选来源、串联转换、查映射表、逐项映射列表，按上游样例实时预览；「AI 自动映射」的建议要逐条确认。
- 触发器的「运行设置」：幂等去重（推荐去重键、预览键值、显示最近拦截的重复事件）、并发上限和保序键；定时任务还能设置「上一次还没运行完时」怎么处理。
- 「AI 智能体」节点：配置指令和任务输入；「工具」里添加连接器操作、外部 MCP 工具或子流程，写入类工具默认需要人工确认；「护栏」限制最大步数、Token 预算，并设置审批人和超时。
- 右上角「AI 助手」：解释工作流、诊断最近一次失败（给出根因和能直接执行的修复）、按描述修改工作流。修改先列成变更清单，可以在画布上标出，确认后才应用，能撤销；做不到的请求会直接说明。
- AI 生成或 AI 助手加上的节点标着「待确认」，逐个检查后确认；有未确认的节点时，发布会先提醒。
- 右键节点：复制、剪切、粘贴到上方或下方；也支持 `⌘C / ⌘X / ⌘V`、`Delete`、`⌘Z / ⇧⌘Z`（Windows 上显示为 Ctrl）。粘贴时节点之间的引用会自动改到新节点上。
- 「错误处理」选「添加分支」或「重试后添加分支」后，画布上该节点下方出现「异常处理」分支。「一键应用」把策略复制给同一连接器同一操作的其他节点。
- 编辑后撤销回原样，「有更新未发布」会消失（按和已发布版本的差异判断）；删除被后面节点引用的节点前，确认框会写明有几个节点引用了它；被他人锁定时，AI 助手的「进入编辑后应用」会说明原因，不再是死按钮。
- 警告（例如连接授权过期、飞书缺少权限）在画布节点上显示黄色标记，节点面板的对应页签带黄点，不只在校验面板里；错误是红色。
- 分支节点从互斥切到并行时会确认：「默认」分支会变成始终运行的普通分支，切回互斥可以恢复。AI 助手应用的修改被撤销后，建议卡片会恢复成「应用修改」，可以再次应用。
- 调试弹窗里「会真的执行 N 个写操作」按你选的这条记录会走的分支统计。
- 「校验」面板列出全部错误和警告，点一条定位到节点。有错误时不能调试和发布。
- 「调试」：先选「用这条数据试跑」——从北森、飞书读最近几条真实记录（只读），也可以自己填；带提示的记录（部门在映射表里没有对照、没有手机号）用来看出错时的样子。双环境项目再选运行环境（测试环境自动换成测试账号）。弹窗会列出这次会真的执行的写操作和它们用的连接；测试环境没替换连接时会警告「和生产是同一个连接」。→ 画布上逐个节点跑动画 → 调试记录面板看每个节点的 Input / Output / Error。映射对不上（例如部门没有对照）时对应节点失败，并写明原因和修法；分支按调试数据判断走向；敏感字段按平台规则脱敏，查看原文要有权限并写审计。
- 发布：只有生产环境的项目「发布」即启用；双环境项目「发布到测试」，弹窗里列出本次改动和测试环境的连接替换（有写操作没换连接时警告），验证后「推广到生产」（生产可能需要审批）。「测试环境验证」里除了真实运行，也算上在测试环境调试过、且内容没改过的记录。「版本管理」可以查看快照、对比任意两个版本、回滚（生成新的版本号，不改写历史）。
- 编辑锁：别人正在编辑时只能查看，顶部显示是谁在编辑；项目所有者可以接管。
- 画布：拖动平移、`⌘` + 滚轮缩放、缩略图（可拖动）、适应画布、折叠全部分支、网页全屏。

其他页面：

- 问题中心：失败按原因聚合，连接认证失败按连接合并；可以按状态、负责人、环境筛选，批量指派、静默、解决。问题详情有 AI 根因分析、可执行的修复、发生趋势、受影响的运行、合并了多少次失败的告警记录和时间线。已解决的问题再次出现会自动「复发」。
- 批量重跑：先做检查，已删除、已停止、连接没修好的运行会被排除并写明原因；目标系统里的数据问题（例如金蝶里物料未审核）改工作流不会让结果不同，归入「大概率失败」；重跑记录沿用原运行的业务标识，问题的影响次数按触发次数算，不把重跑当成新的失败；同一次触发的多次尝试只重跑最近一次。可以选「从失败节点重跑」或「整体重跑」、原版本或最新版本、并发数。
- 告警策略：聚合窗口、静默时段、升级规则、通知渠道（飞书、企业微信、钉钉、Slack、Webhook、邮件），被策略使用的渠道不能删除。
- 运行日志：筛选条件里的「业务标识」按工号、审批单号、姓名搜，可以只输一部分；列表有「业务标识」列，重试和去重的运行沿用原运行的标识。详情里点「这条记录的全部日志」看同一个人、同一张单的所有运行。多选批量重跑；详情里有「从失败节点重跑 / 整体重跑」、沿用原结果的节点、已去重的运行（能追到第一次处理它的运行）、环境、脱敏与查看原文、智能体的批准与拒绝和它的调用步骤；日志按保留期显示。
- 发布与审批：审批人在发布详情里看差异、检查结果和测试环境运行记录后批准或驳回，申请人可以撤回。环境与配置里可以设置审批人、测试环境的连接替换，开启或关闭测试与生产环境。
- 映射表：行内编辑，拒绝空键和重复键；导入 CSV 先预览再合并或替换；导出是真实下载；「被引用」列出用到它的工作流节点。
- 项目侧栏：文件夹最多三层；工作流可以拖进文件夹；「批量操作」后可以批量发布（双环境项目只发布到测试）。工作流可以导出为 JSON，再导入到其他项目。
- 统计口径：问题中心、日志、监控的「近 7 天」都按含今天的 7 个自然日，失败都包含超时；问题列表的「累计影响」是这个问题出现以来的触发次数；告警记录里「覆盖 N 次失败」不会超过问题本身的失败次数，不同策略的告警覆盖范围有重叠时会说明。监控的「峰值并发」分母是在线节点的容量，用量页的并发上限是实例设置，实际生效的是较小的。
- 运行监控：按本地时间分桶的趋势图和表格视图，可以保存自己的视图；「AI 用量」按模型、来源（工作流运行、编辑器 AI 助手、AI 自动映射、AI 生成工作流）和工作流统计 Token，单价估算只存在页面里，不涉及计费。
- 连接：分享给同事时区分「可使用」和「可编辑」；「被引用」除了工作流，还算上测试环境的连接替换、MCP 服务的固定连接和项目配置项，有任何一处在用就不能删除，并列出引用方；状态分「已连接 / 已过期 / 异常」；过期或异常的连接，有编辑权限的人在详情里重新授权（预填服务器、账号这些不变的信息，只更新凭证，换账号要新建连接），只有使用权限的人可以「提醒所有者重新授权」，对方会收到通知。
- 外部 MCP 服务器：接入时校验地址、传输方式和认证，连接测试会指出 localhost、内网、云元数据地址、域名解析、401 等真实原因；详情里可以同步工具、试用工具、改设置，被工作流或智能体使用时不能删除。
- 连接器开发：新建连接器（也可以从 OpenAPI 导入）、认证开发五步、操作入参在工作流编辑器里生效、两步发布（勾选变更、看真实差异），支持灰度发布和停止支持。
- MCP 服务：从连接器或子流程工作流新建工具；每个服务有自己的 API Key；「使用方式」里有 Cursor、Claude Code 和通用 HTTP 的配置片段。
- 管理后台：登录方式按「邮箱和密码 → OIDC → SAML → 飞书 → 企业微信 → 钉钉」排列，都要先配置才能启用，登录页只显示已启用的方式；系统与升级、备份与恢复、数据与隐私见上面的场景 5、6；品牌外观改产品名、Logo、欢迎语和主题色后，登录页和控制台跟着变。

## 方案的交互逻辑

方案是装上就能用的一组工作流、映射表和告警策略，对应 AnyCross 的「集成方案」。入口：左侧栏「方案」。

**安装**（`#/solutions/beisen-feishu/install`），五步，上一步随时能回去改：

1. **选择项目**：装到已有项目（只列出有编辑权限、没到工作流上限的项目），或新建一个项目。下方预告装完会多出什么；同名工作流自动加后缀，不覆盖。
2. **连接**：方案用到的每个系统选一个连接，或当场「新建连接」，建好自动选上。选了失效的连接会直接写出原因，不能进下一步。
3. **配置**：表单由方案的配置项生成，每项写明影响哪些工作流。选危险项（离职「直接删除账号」）会当场提示后果。
4. **安装检查**：逐项自动检查。标「必须」的不通过就不能安装；「建议」的可以跳过，跳过的会记在安装记录里。没通过的项给出处理步骤、谁来处理，可以「复制给飞书管理员」，处理完点「重新检查」只查这一项。演示里「通讯录权限范围」第一次不通过，重新检查后通过；「IP 白名单」平台确认不了，一直是建议。
5. **完成**：工作流全部是未启用的草稿，连接已经填好。逐个「打开调试」，确认部门映射表里自动匹配不上的部门，再启用。告警策略装完就启用。

装出来的工作流不是空壳：每个节点的字段映射、去重键、保序键都配好了，安装时填的配置项真的会改变结果（选「直接删除账号」，装出来的离职工作流就是删除账号；选「入职当天」，开通时间就是当天 08:00）。方案的映射表按「键和值的含义」和项目里已有的表比对，已经有同样的表就沿用，不再建重复的。

**升级**：方案出了新版本，「已安装」列表和方案详情会出现「升级」。升级会把新版本的改动放进工作流的草稿（例如「每日考勤异常提醒」v1.1 给查询 SQL 加上 minutes > 10），线上运行的版本不变，调试后发布才生效；连接、配置、映射表内容沿用；草稿里已经有没发布的改动时先提醒。

**基于项目生成方案**：方案页右上角。选来源项目和工作流 → 补充安装检查项（「连接可用」自动加上且必须通过）→ 填名称、分类、可见范围后发布。凭证、项目配置的值和运行日志不会打包。来源项目改了以后，在方案详情点「发布新版本」，装过的项目就会看到可以升级。

## 和 AnyCross 的对应与取舍

- **术语**：跟本仓库现有中文词汇走。「工作流」「项目」两边一致；AnyCross 的「应用凭证」这里叫「连接」。「项目配置」保留原名，它就是本仓库的 Variables；AnyCross 的「配置组」升级为「环境」，带连接替换和审批。
- **发布**：只有生产环境的项目保持 AnyCross 的发布即启用；需要管控的项目开启测试与生产环境，发布先到测试，再申请推广到生产。部署和启停混在一起，对生产系统风险太高。
- **告警**：AnyCross 用「告警触发器」工作流发告警。这里平台内置问题中心和告警策略，负责聚合、降噪和复发识别；更复杂的需求仍然可以用告警触发器工作流（示例：「工作流运行失败告警」）。
- **不以飞书为中心**：飞书是若干即时通讯之一。登录方式、通知渠道、告警、模板都同样支持企业微信、钉钉、Slack，AI 助手按描述里提到的工具选择连接器。
- **MCP 双向**：除了把连接器和工作流开放成 MCP 工具，还可以把外部 MCP 服务器接进来当连接器用，「AI 智能体」节点在护栏内调用这些工具。
- **不做**：数据集成（产品范围明确排除）。
- **暂不做**：身份集成（给其他应用做单点登录的身份源）、服务商。这两个是 AnyCross 在 iPaaS 之外的业务线，本仓库没有对应能力。
- **方案**：照 AnyCross 的集成方案做（方案市场、基于项目生成、安装向导、安装检查、版本）。去掉跨企业上架和付费方案；安装检查分「必须」和「建议」，建议项可以跳过；装完的工作流一律不启用，升级只换草稿。
- **改造**：本地代理服务改成「工作节点」，添加节点的向导沿用 AnyCross 的「基础配置 → 安装 → 连接测试」三步。
- **去掉付费**：AnyCross 的权益管理有套餐和加油包，这里只显示实例级上限和项目级上限，没有任何升级入口（见 `docs/adr/0002`）。
- **去掉跨企业上架**：自托管部署没有面向其他企业的市场，自定义连接器只在本企业内公开；连接器仓库只用来获取官方连接器，没配置时显示为未启用。
- **补齐**：审计日志、数据加密、数据与隐私、系统与升级、备份与恢复、品牌外观，AnyCross 没有公开页面，按本仓库的多租户、自托管和白标要求补上。
- **异常处理分支**：AnyCross 的文档站是前端渲染，没拿到原文。这里按常见语义实现：节点出错时进入画布上的「异常处理」分支，分支跑完后继续运行后面的节点。
- **视觉**：主色、字体、圆角、阴影全部用本仓库设计系统；只有布局、信息架构和交互照 AnyCross。

## 改原型时注意

- 所有脚本共享一个全局作用域。新增顶层函数或常量前先全局搜索有没有重名，重复的顶层 `const` 会让整个原型白屏。页面文件里的新名字建议带页面前缀（例如 `logs…`、`sys…`）。
- htm 模板只能有一个根节点。多个根（包括元素旁边的一段文字）会返回数组，触发 React key 警告，用 `<${Fragment}>` 包起来。
- 改了演示数据的结构，要同时把 `core.js` 里的 `STORE_KEY` 版本号加一，否则已有的 localStorage 数据会按旧结构渲染出错。
- 工作流的 `version`、`published`、`status` 始终指生产环境；双环境项目的测试部署在 `wf.test`，版本记录的 `envs` 记录部署过哪些环境。
- 通知带 `userId` 时只有接收人能看到，不带时视为发给当前登录用户。
- 没有构建和类型检查。改完至少做三件事：把 `index.html` 里的脚本按顺序拼成一个文件跑 ESLint（`no-undef`、`no-redeclare`、`no-unused-vars`）；用 React 开发版打开改动涉及的页面，看控制台有没有报错和 key 警告；亮色和深色各截图看一遍，控制台干净不代表样式没丢。

## 已知限制

- 没有后端，所有数据都是演示数据。调试、测试连接、OAuth 授权、MCP 工具发现、检查更新、备份和恢复都是模拟的；导出工作流、导出映射表、下载诊断包会真的下载文件，导入也读取真实文件。
- AI 规划、AI 映射建议、根因分析和编辑器 AI 助手都按规则模拟，不调用真实模型，Token 数是估算值。
- 定时任务的触发预览不排除法定节假日（没有节假日日历）。
- 成功和失败两种状态色对红绿色弱的人区分度不够，图表和列表用图标、图例和顺序做了补偿，颜色本身沿用设计系统。
- 原型没有做响应式，建议在 1280px 以上的宽度查看。
