## Decision

一个实例可以承载任意多个互相隔离的租户。iPaaS 保留完整的账号、租户和权限体系，同一套代码有两种用法：

- **独立出售**：自己的账号体系，支持自助注册建租户，租户自己配置单点登录。
- **FEMA 套件**：和 fema-bpaas、fema-apaas 组成闭环，按 `fema-bpaas/docs/design-iam-ipaas-federation-2026-11-04.md`（2026-11-05 确认）运行。fema-iam 是身份源，两边的租户一一对应；人按 issuer + sub 认（决定 000046）；租户、登录配置和连接由业务方的租户初始化调用平台开通接口一次建好（决定 000047）；fema 的业务事件以签名 webhook 推给 iPaaS，触发流程。

两种用法之间不设开关，也不分版本。区别只在于实例运营者配置了什么、开通了哪些租户。

**实例运营者**是新增的实例级角色，负责建立和停用租户、调整容量、签发平台调用凭证，以及管理全实例共享的设置：工作节点、备份、短信、人机验证、平台登录应用、是否开放自助注册。原来的"主租户"（最早建的租户）概念取消。

**租户识别**：已登录的请求按令牌认租户。未登录的请求依次看：显式指定的租户（`tenant` 参数或 `/t/<租户标识>`）、访问域名（已验证的租户域名，或实例基础域名下的子域名）、邮箱域名发现（只认已验证的登录域名）。实例里只有一个租户时就用它，这样自部署不需要任何配置。以上都定不了时，先认身份，再让用户选租户，不再落到最早的租户。

**登录方式**：没配置的方式一律隐藏。

| 方式 | 谁来配置 |
| --- | --- |
| 邮箱 + 密码、邮箱验证码 | 实例开关，租户可以关闭 |
| 手机号 + 短信验证码 | 实例运营者配置阿里云或腾讯云短信 |
| 飞书、企业微信、钉钉 | 实例运营者配置平台应用（扫码登录，按企业认租户）；租户也可以配置自建应用 |
| OIDC（含 fema-iam） | 租户级；fema-iam 由开通接口写入，每家租户一个客户端 |
| SAML 2.0 | 租户级 |
| 两步验证（TOTP） | 账号自己开启，租户可以强制 |

**人机验证**改为平台自建的工作量证明，不依赖外部服务，零配置可用；Cloudflare Turnstile 保留为可选项。

不做 Google、GitHub 等境外社交登录。

## Context

改动前，数据层已经按租户隔离，但 `POST /v1/tenants` 只认第一个注册者的引导令牌，未登录的请求一律落到 `getOldestTenant()`，所以第二个租户实际无法使用。产品要 SaaS 化，要和 FEMA 的 bPaaS、aPaaS 组成闭环，同时要能单独出售。

## Why

"能单独出售"决定了身份不能外包给 fema-iam。否决的方案是直接以 fema-iam 为唯一账号源：那样单独卖 iPaaS 时，就得把 fema-iam 一起交付。现在的做法下，fema-iam 只是一个按标准 OIDC 接入的身份源，客户自己的 IDaaS 走的也是同一条路。

## Consequences

- 自部署的默认行为不变：只有一个租户，不开放自助注册，不需要新增配置（`self-hosting.md`）。容量上限照旧放在租户和项目上，不按套餐区分功能（ADR 0002）。
- 不做内网代理节点，ADR 0018 不变：云上的 SaaS 实例只对接公网可达的系统，要接客户内网系统的客户使用自部署版。
- 邮箱不再是账号的必填项：只有手机号的账号、fema-iam 成员都可以没有邮箱。没有邮箱的账号收不到邮件通知。
- 工作节点整个实例共享，所以要按租户限流和分配配额；大客户可以通过 `workerGroupId` 分到专属节点组。
- 代码步骤会执行陌生租户的代码，沙箱强度要按 SaaS 的威胁模型重新评估。
- 计费不放在 iPaaS 里。iPaaS 只导出按租户统计的用量，并执行租户上的容量上限。
