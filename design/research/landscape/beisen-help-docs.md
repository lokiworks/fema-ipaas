## 要点

**新旧接口。** 北森现在有三套对外接口：新版 V3（`open.italent.cn` 站点，覆盖组织员工、薪酬、假勤、绩效、继任与发展、Account、新招聘）、老版 V2（`openapi.italent.cn`，只维护存量客户，不再迭代）、招聘 2.0（集团版招聘，同样只维护存量）。文档明确写「新对接客户都通过新版接口对接」，对接流程只适用于 V3。

**调用流程。**

1. 北森实施顾问或租户管理员在 italent 的「企业设置 → 授权管理」里，给某个账号授予「开放应用连接」租户管理员身份。
2. 用该账号登录开放平台的管理者后台，创建连接器，拿到 Key 和 Secret。
3. 在连接器详情里逐个添加要调用的接口权限。
4. 可选：在「OpenAPI 调用授信 IP」里加调用方的 IP 段。
5. `POST {域名}/token`，请求体 `grant_type=client_credentials`、`app_key`、`app_secret`，换 `access_token`。
6. 带令牌调用各模块接口。

**三套环境。** 正式租户和测试租户共用同一个生产接口域名，只是租户不同，测试租户由北森实施顾问开通。沙箱环境是单独的域名（`openapi.italent-dev.cn`，令牌在 `/token`），只有买了 PaaS 平台的客户才有。没有北森租户的开发阶段，只能用本仓库的模拟服务。

**限频。** 每租户每接口 50 次/秒、3000 次/分钟，具体以各接口文档为准。同一租户下多个连接器加了同一个接口，一秒内累计不能超过 100 次。触发后返回 `429 API rate limit exceeded`，文档的说法是当天不再能调用，次日零点恢复。

**组织员工主数据同步的官方推荐做法。** 用时间窗滚动查询接口拉取变动的组织单元、员工与单条任职、职位、职务；要员工历史任职记录，改用「员工与多条任职」接口。文档没有推荐事件推送。相关子问题包括 `startTime`、`stopTime`、`timeWindowQueryType`、`scrollId` 的含义，如何区分待入职、试用、正式、退休、离职、外部员工，以及自定义字段为什么没返回编码和值。

**支持渠道。** 先用 Postman 之类的工具用同样入参自查；仍然不通，发邮件到 `supportapi@beisen.com`（承诺 24 小时内回复，要附业务场景、接口、请求内容、报错和出入参），或通过实施顾问提交付费工单（需提供对接方案）。

## 对本仓库的影响

- **取令牌字段已被官方文档证实。** 连接器用的 `app_key`、`app_secret`、`grant_type=client_credentials` 与「接口调用流程」一致，此前靠故意发错误请求探出来的结论（见 `brain/knowledge/connectors-engine/building-connectors.md`）现在有一手来源。
- **沙箱接口地址可以直接填。** `FEMA_BEISEN_BASE_URL` 设成沙箱域名即可，不用改代码；但沙箱要购买 PaaS，不能当作默认的联调方案。
- **自托管用户要登记出口 IP。** 授信 IP 是可选项，但很多租户会开。平台所在机器的出口 IP 变了（换云、换节点），北森会返回 403，要让运维记得去开放平台后台更新。
- **429 已按「当天不可恢复」处理（连接器 0.2.1）。** `beisenCommon.callApi` 把 HTTP 429 和 200 响应体里的 `API rate limit exceeded` 都转成 `HTTP 429: ... 次日 00:00 才能再调` 的错误，问题中心按 HTTP 状态归类，不会当成可立即重试的普通失败。限频来源是每租户每接口 50 次/秒、3000 次/分钟，取令牌的请求没有做这个转换。主线按时间窗滚动拉取，分页越多越容易触发，补跑大量历史变动时仍要先估算调用量。
- **组织员工接口有过参数调整公告。** 「重要升级通知」那一页未读，改动连接器里的组织员工动作前先读它。
- **不能凭域名判断连接器的动作属于 V2 还是 V3。** 「对接环境准备」把 `openapi.italent.cn` 写成生产环境的接口域名，「开发前须知」又把它列为老版 V2 的文档地址，V3 的接口说明则在 `open.italent.cn`。动作路径是否都是 V3，需要登录开放平台文档站点或拿到真实租户核对，现在不能断言。
