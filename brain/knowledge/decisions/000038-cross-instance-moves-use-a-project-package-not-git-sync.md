title: 跨实例迁移用项目包，不重建 Git 同步
icon: 🧳
status: accepted
---

## Decision

首发只支持单实例内的测试与生产双环境，不做跨实例推广。测试和生产是两套部署的客户，第二阶段用「项目包」导出导入：包含工作流、变量名、映射表和连接占位，导入时逐个绑定连接。不重建上游的 Git 同步。

## Context

单实例内的环境、连接替换、审批和回滚已经实现。现有导出只有单个工作流的流程图，不带变量、映射表和连接占位，搬不动一个完整项目。上游的 Git 同步和 environments 已经删除（000030）。

## Why

目标用户是集成工程师和值班运维，不是习惯 Git 工作流的开发者；项目包是一个文件，放得进客户的变更审批流程和隔离网络。否决的是重建 Git 同步：它要求两套环境都能访问同一个 Git 服务，冲突处理也把复杂度推给了用户。

## Consequences

- 项目包的格式一旦对外就要保持兼容，需要版本号。
- 跨实例的推广没有审批记录，审批留在目标实例的发布流程里做。
